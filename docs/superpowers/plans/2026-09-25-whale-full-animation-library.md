# 鲸鱼娘完整动作与表情库方案（暂缓实施）

状态：用户要求先保存方案，后续再做。2026-09-25。本次只修复现有睡眠闭眼表现，不启动本方案，也不把候选路线视为已经选定或完成。

## 目标与身份

目标是丰富、完整、可以持续扩充的全身动作与表情库。抱食、挥手、蜷睡、伸懒腰只是代表动作，不是范围上限；原先的 24 动作 / 12 表情也不是数量上限。

保持用户认可的待机形象、头身比例、五官、蓝发与鲸鳍耳、白色头饰、服装、鲸尾及柔和笔触。遵循 [设计语言](../../design-language.md) 与 [desktop-live2d-pet feature](../../features/desktop-live2d-pet.md)。现有待机母版不得被候选图覆盖。

## 建议制作路线

多姿态角色原画 + 骨骼与网格变形 + 独立表情控制 + 少量逐帧过渡。

1. 固定角色设计和比例，制作统一的多姿态参考；新增角度、手势和被遮挡部位需要补绘。
2. 准备直立漂浮、侧身、坐姿、蜷卧、悬挂、抱物等基础姿态。不能仅靠拉扯一张站姿完成所有动作。
3. 分离手臂、手掌、腿、躯干、头发、裙摆与尾巴，建立关节、遮挡顺序和变形范围。
4. 通过骨骼、网格权重与关键形态制作连续变形；尾巴、头发、衣摆保留不同的跟随节奏。复杂转身或姿态跨度用专用绘制与过渡帧支持。
5. 表情与身体动作分层组合，保留眨眼、视线和呼吸；组合须符合动作语义，不能让熟睡叠加惊讶、跟随视线或随机笑眼。
6. 应用使用可中断、有进入 / 持续 / 退出的动作控制；抓取、拖动与抛掷读取实际指针及物理状态，不能只播放固定轨迹。

针对全身动作较多的目标，优先评估 Spine 骨骼与网格方案；Cubism 的网格变形与姿态部件切换为另一候选。工具尚未选定，也未授权购买或迁移。现有 Electron 窗口、交互与物理基础可复用，THA4 的保留方式在样片验证后再决定。

此前刚性部件木偶和跨画风活头拼接均已被用户否决。新方案必须验证关节连续变形、身体重心、次级运动和形象一致性，不能将旧方案换名重交。

独立动作、动作阶段、过渡与重复变体分别记录；不以标签数量或组合乘积宣称完成数量。

## 验证与后续实施顺序

先制作覆盖不同难点的一组样片：挥手验证关节；抱食验证手物接触与遮挡；蜷睡验证身体变形；起身验证姿态切换；抓抛验证实时响应。这组样片用于验证制作方法，完整动作库仍是交付目标。

每组需在实际桌面尺寸与放大尺寸同时审查，检查五官位置、比例、笔触、服装、尾巴、关节和遮挡；关闭文字与特效后仍应认得出动作。连续播放需检查进入、循环、退出、打断和返回待机，不能仅检查静帧或边界。

样片通过后才按完整清单扩展，接入实际用户触发路径；最后做应用回归、性能与透明窗检查。代码测试只证明工程契约，不能代替美术验收。

## 替代路线与未解决事项

- 全逐帧动画：表现自由，但动作规模扩大时，绘制与一致性维护成本同步增长。
- 三维模型：大幅运动和转向更方便，但复现当前二维形象与柔和质感需要额外制作。
- 继续只扩 THA4 状态参数：可改善表情和小动作，无法承担本方案所需的全身姿势。
- 批量独立生图：可辅助草稿和补绘；此前候选存在身份漂移和帧间差异，不能直接充作完整动画。

当前缺口是合格的多姿态分层美术和动画资产。仅靠现有生图工具自动完成整套高一致性资源的可行性尚未证实。工具、资产制作方式、质量、工作量与运行时方案需以样片证据确定，不承诺固定数量或时限。
