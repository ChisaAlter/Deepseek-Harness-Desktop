## 发布顺序约束

当前 `.github/workflows/release.yml` 在推送 `v*` 标签后重新构建并自动公开 Release，**不能先打标签再补验收，也不能验收后重新出包换掉文件**。

应采用不触发 tag-push 构建的手动同包晋级路径，并显式固定候选 SHA；或先另行确认 promotion workflow 的改动范围。本文不执行任何一种发布操作。

本版取消 macOS 只改变发布资产范围，未修改 workflow 的双平台构建逻辑。后续不得直接推标签走自动发布，否则仍可能上传 macOS 产物，且会绕过同包验收顺序。
