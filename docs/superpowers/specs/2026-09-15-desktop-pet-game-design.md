# 桌面宠物「鲸鱼娘」游戏设计（GDD）

> 对现有 Live2D 桌面宠物（`desktop-live2d-pet`）的正式设计定稿 + 数值审查 + 改进提案。
> 方法框架：MDA / Bartle / 核心循环 / 经济水龙头-水槽 / 奖励节奏（参照 edhahn/agent-skills `game-designer` 与 fcsouza/agent-skills `game-design-fundamentals`）。
> 现状事实以 `docs/handbook/modules/desktop-pet.md` 与源码为准。

## Elevator Pitch

一只住在你桌面上的 DeepSeek 鲸鱼娘：你正常工作、用 Harness 聊天烧 token，token 就是她的口粮；闲了摸摸她、逗逗她、把她拎起来扔出去，她会长大、变黏、记住你对她的好。**她把"使用产品"本身变成了养成资源**——这是她和一切普通桌面宠物的根本区别。

一句话：**你的算力消耗，养成一条鲸鱼。**

## 设计定位

| 项 | 定调 |
| --- | --- |
| Core fantasy | 养一只慵懒、傲娇、依赖你的鲸鱼娘；"被需要"的陪伴感 |
| MDA 目标美学 | **Submission**（挂机陪伴/低压力）+ **Fantasy**（扮演饲养员）；辅：Discovery（台词图鉴） |
| Bartle 主类型 | Socializer（陪伴互动）+ Achiever（等级/亲密 ladder）；Explorer 弱覆盖（370 条台词） |
| 压力哲学 | **轻度压力**：会饿、会闹别扭，但不死不病不惩罚——桌面伙伴不是电子宠物监狱 |
| 平台语境 | 生产力工具的挂件：互动必须 5 秒内完成、不可打断心流、默认穿透不挡桌面 |

## 核心循环

### 30 秒循环（微观手感）

```
碰到她 → 即时的 juicy 反馈（表情/爱心/喷水/抛掷物理）→ 台词气泡 → 还想再戳一下
```

现状评估：**强**。神经动画 + 立绘混合 + 粒子 + 抛掷弹道，手感层完成度高，是整套设计的根基。

### 会话循环（每次使用 Harness）

```
工作烧 token → 状态卡攒出【投喂 +N】→ 投喂仪式（晶体落下→跑过去吃→升级庆祝）
→ 属性条上涨 → 继续工作
```

现状评估：**成立且有特色**。token→口粮的兑换把产品使用与宠物养成焊在一起，是最有辨识度的机制。隐患见「问题 P1」。

### 长期循环（跨天/跨周）

```
每日回来喂饭（饱食 −3/h ≈ 33h 见底 → 天然日返钩子）
→ 十级称号 ladder（幼鲸→…→干饭真神，0/1亿/3亿/6亿/12亿/22亿/40亿/70亿/120亿/200亿）+ 五级亲密 ladder（陌生→…→形影不离）
→ 集齐台词/解锁满级状态
```

现状评估：**有骨架、缺终局**。两个 ladder 都会封顶，封顶后只剩日常维护（见「问题 P4」）。

## 机制清单（现状审查）

### M1 点按 / 连戳

- 输入：单击；输出：四表情轮换 + tap 台词；连戳 4 次/3s → 生气 + 喷水。
- 动机：即时反馈的触感；喷水彩蛋奖励"过度调戏"。
- 边缘：拖拽 <4px 视为点按——拖歪了变戳她，合理。

### M2 摸头

- 输入：头顶 45% 区域 1.6s 内 3 次变向；输出：摸头立绘 + 爱心 + pat 台词。
- 动机：关系表达动作（手势语义化，不是按钮）；隐性教学——玩家自己"发现"摸头手法是惊喜时刻。
- 边缘：面板动作格也有「摸头」按钮，两条路径并存（手势=发现层，按钮=可达性兜底），合理。

### M3 拖拽 / 抛掷

- 输入：抓起（>4px）→ 松手；输出：速度 ≥500px/s 进弹道（重力/反弹/摩擦），慢放则原地落下。
- 动机：玩具性（toy value）——无目标玩法本身就是乐趣；物理参数调得偏夸张（恢复系数 0.78）读感好。
- 边缘：空中可抓回（仁慈设计）；跨屏拖拽 overlay 跳屏不中断。throw 计入 care（心情 −9 亲密 +1）——"打是亲"的混账逻辑，拟人感对。

### M4 算力投喂（核心经济机制）

- 输入：状态卡【投喂 +N】；输出：token 晶体落下 → 她跑去吃 → 成长点 +N（一餐最多升一级）→ 升级庆祝 + 称号变色。
- 动机：把"我聊了多久"变成可见的养成成果；每餐=一次升级仪式，不做批量吞噬，是对的克制。
- **临界问题：她是唯一能吃的口粮只有 token。** 见 P1。

### M5 睡觉 / 叫醒

- 输入：4min 无互动自动睡；碰醒或点醒；输出：sleep 立绘 + Zzz + 叫醒 −7 心情。
- 动机：生物钟让她"活着"；叫醒惩罚是傲娇人设的一致性表达（naps are sacred）。
- 边缘：睡觉前睡前台动作全部清空，状态机无残留——现实现正确。

### M6 叫过来 / 玩耍 / 逗她（面板动作格）

- 输入：chip 点击；输出：跑步寻主 / 庆祝蹦跳（耗饱食换心情）/ 随机反应（心情 <25 时反噬炸毛）。
- 动机：低成本的主动照顾入口；tease 的条件反噬是属性影响行为的最直接体现。
- 边缘：与手势层（摸头/点按/抛掷）重复但不冲突——按钮是明确性兜底。

## 系统审查（数值）

### S1 Token 经济（faucet / sink）

```
水龙头：dsh-home 会话日志的真实 usage（input+cache+output），扣除历史水位线
水槽：  一餐最多填满当前级（防一口吃满，保证每餐=一次仪式）
```

- 1 token = 1 成长点；十级阈值 0 / 1亿 / 3亿 / 6亿 / 12亿 / 22亿 / 40亿 / 70亿 / 120亿 / 200亿（级间餐量 ~1.7x 递增：1→2→3→6→10→18→30→50→80 亿，累计恰 200 亿满级）。
- 节奏量化（重标定）：本设计面向重度深度用户——~500万 token/天 约 40 天满级，~2000万/天 约 10 天，轻度用户则长期停留在中低段（这是刻意的：天梯拉长后"毕业"是稀有的，参考原六级评估"约 4 天满级"过快）。级间餐量单调递增且倍率 ~1.7x 恒定，曲线形状健康。
- 每餐锁一级的副效果：feedable 再高也强制 ≥9 次投喂动作——把消费行为切成 9 份快乐，好设计（注：单次投喂最多填到下一级门槛）。
- 水位线逻辑（baseline=语料−已喂、只降不升、tokensFed 不回退）防了"删日志重喂"和"升级后历史变口粮"两类作弊/不公，严谨。

### S2 养成属性（饱食/心情/亲密）

| 属性 | 衰减 | 现状评估 |
| --- | --- | --- |
| 饱食 | −3/h，~33h 到底 | 日返钩子成立；但**没有非 token 进食途径**（P1），且饿了只有台词差别、无实感（P2） |
| 心情 | 向 62 回归 ±8/h | 均值回归=慵懒人设的数值化，对；线性回归简单可靠 |
| 亲密 | 不衰减；同类 10min 冷却期内 25% 效率 | 防刷机制在位；永不衰减对伙伴类正确；满级后无新内容（P4） |

### S3 台词/奖励节奏

- 固定比率奖励：升级、亲密称号（可预期的里程碑）✓
- 可变间隔奖励：闲聊 3–6min、小花招 25–45s、随机小动作 5–10s ✓
- **缺失：可变比率惊喜**——没有低概率稀有事件（见提案 R4）。
- hungry/grumpy/clingy 三个状态池把属性转译成语言层，是"系统→叙事"的正确做法。

## 问题清单（按严重度）

| # | 问题 | 影响 | 证据 |
| --- | --- | --- | --- |
| P1 | **没有非 token 喂食途径**。`startFeed('rice')`（白米饭）是死代码——UI 不可达。不烧 token 的用户饱食归零后永远无法喂她 | 轻度用户/出差周：她永久饿着，设计承诺破裂 | `pet-live2d.js` 中 `startFeed` 仅被 `onGrowthPush` 以 `'token'` 调用 |
| P2 | 饥饿无实感。satiety<20 只提高 hungry 台词概率，视觉上她照样蹦跳 | 压力系统形同虚设，照顾动机弱 | `tickStill` 中无 satiety 相关的视觉调制 |
| P3 | 无每日首互动奖励。日返只有"她会饿"的负面推力，没有正面拉力 | 留存钩子单一 | care 无 day-boundary 奖励逻辑 |
| P4 | 双 ladder 封顶后无终局内容。干饭真神 + 形影不离后只剩维护循环 | 长期用户失去目标 | LEVELS/AFFECTION_LEVELS 均为有限表，无溢出处理 |
| P5 | 成长无视觉锚点。六级只换称号颜色和徽章，她本体一个像素都不变 | 进度感弱于预期（"长大了"看不见） | PET_W/H 常量，无等级缩放 |

## 改进提案（按性价比排序）

### R1 接通白米饭喂养（修 P1，强烈建议）

面板动作格把「隐藏」行扩成「米饭」+「隐藏」，或投喂区加副按钮【喂米饭】：

- `startFeed('rice')` 表演与台词池（feed/feedEat/feedDone）**现成未用**，直接接线；
- 数值：+15 饱食、+3 心情、+1 亲密，**不给成长点**；
- 每日上限 2 次（`stats.care.rice` 时间戳判今日次数），保持 token 投喂的主地位——米饭管活命，算力管长大；
- 米饭免费但有限：保证"出差一周回来她还活着、但等级原地踏步"的公平性。

### R2 饥饿可视化（修 P2）

- satiety<20：闲聊 hungry 概率 55%→75%，叠加偶发"蔫"立绘（复用 tail-swing 慢速版或新 still）；
- satiety<20 时心情额外 −2/h 衰减（饥饿→闹情绪的系统耦合，涌现感）；
- 饿到 0 超过 24h：醒来第一句固定是抱怨饿（一次性台词，不重罚只扎心）。

### R3 每日首互动奖励（修 P3）

`stats.care` 已有 kind→ts 表，加 `dailyFirst`：本地日第一个有效 care 动作亲密 ×1.5（向上取整）。面板今日消耗行旁边加一行小字「今日已贴贴」。成本极低，日返正拉力成立。

### R4 稀有台词（可变比率惊喜）

每类台词池可标记 `rare:0.02` 的金句（约 2% 概率），洗牌袋抽出时按稀有度二次判定。Explorer 型玩家的收集钩子；数据格式向后兼容（普通字符串=无稀有度）。**这是性价比最高的"内容深度"增加——纯数据，不动系统。**

### R5 满级归宿（修 P4，开放问题，需拍板）

两个候选，二选一或都做：

- a) **威望星环**：满级后继续喂，每 100 万 token 换一颗星标（称号行 ★ 计数）——纯荣誉 sink，不新增系统；
- b) **体态成长**（兼修 P5）：每级 +6% 渲染尺寸（PET_W/H 按 level 缩放 1.0→1.36），干饭真神肉眼可见地大一圈。改动集中在渲染常量与命中区计算，中等成本，但"长大了"是养成游戏最强的进度证明。

### R6 设计参数外置（工程项）

LEVELS、CARE 表、衰减率、冷却、闲聊间隔目前都是代码常量。逻辑纯化已经做得好（pet-growth/pet-stats 无 I/O），建议把数值表抽到 `pet-tuning.json` 一类数据文件——后续调平衡不用发版改逻辑。

## 不做清单（anti-scope，维持克制）

- 生病/死亡/离家出走——惩罚违背伙伴定位；
- 氪金/商城/内购——红线；
- AI 实时对话/语音——离线红线 + 范围爆炸；
- 多宠物/繁殖/交易——系统工程量与收益不匹配；
- 任务系统/签到 UI——她已经是桌面常驻，不需要 FOMO 任务链。

## 待拍板问题

1. R5 终局内容选星环、体态成长、还是都要？（建议体态成长——可见度最高）
2. 米饭每日上限 2 次是否合适？重度用户可能希望更多免费互动——但米饭不给成长点，多给也无害，可放宽到 3–4 次。
3. 饿到 0 要不要影响成长（如饥饿中 feedable 不累积）？——**建议不要**，惩罚与产品使用强绑定太狠。
4. 稀有台词的内容来源：延续现有原创台词库的作者流程即可，建议每类先加 1 条试点。

## 验收标准（若提案实施）

- R1：饱食 0、feedable 0 的用户点【喂米饭】能完成进食 FSM 且成长点不变；当日第 3 次按钮置灰。
- R2：satiety<20 持续 2h 后心情明显下降（快照可证）；面板饱食条红区时闲聊抽样 hungry 占比 ≥50%。
- R3：同一 care kind 当日第二次触发时亲密增量回到表值。
- R4：whale.json 支持 `{line, rare}` 结构；rare 线概率统计测试可断言。
- R5b：Lv6 渲染尺寸 ≈ 240×260 → 326×354 且不挡屏（clamp 仍生效）。
