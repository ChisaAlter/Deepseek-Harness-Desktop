## User paths

1. 冷启动预创建隐藏启动器并并行检查正式版更新；自动启动且无本地 hold 时立即进入桌面，迟到的新版本提示保留到用户下次打开启动器。关闭自动启动、待导入或上次失败时先显示启动器，新版本只在可见窗口询问；用户确认后安装当次展示的 release，下载或校验失败留在启动器首页，桌面仍可手动启动。
2. 空桌面 `sessions/` 且官方 home / 用户技能根有可导入会话、附件、技能、可重装插件、MCP、白名单设置节、预设或 home `AGENTS.md` 时停在导入，不自动启桌面。导入页分类勾选，可另选来源或技能目录；只拷勾选项到桌面 home。闸门判定用 `probeImportHold` 浅探针（首个命中即返回），不做全量 `scanImport` 元数据扫描。
3. 桌面就绪且「启动后退出启动器」为开 → 关启动器窗，**仅**在完整健康启动（`lastStart.ok===true`、非 sticky skip、非 recovery 启动）时生效。启动失败或 sticky skip 时留在启动器并展开首页 **Recovery Board**（全插件名单、归因、逐项开关、批量禁用可疑）。跳过用户插件后点「启动桌面端」会清 sticky 并强制重启。插件排查与首页共用同一插件名单渲染；禁用/启用在内核 `ready|starting|error` 时经 `startHarness` 对齐名单，**不**走会关启动器的 `startDesktop`。
4. 托盘 / 文件菜单「打开启动器」随时再打开。版本页顶部常驻「本机版本」卡（版本号+状态徽标+安装路径，源码运行时标注 package.json 版本；若注册表有 Setup 则显示其版本与路径），下面是正式版列表——每行可就地展开该版本的发布日期、安装包大小、更新说明与对应操作（更新/切换/增量，有增量资产时才出现增量按钮）；更新询问与首页更新提示携带 release notes。版本页线路切换为页内下拉弹层（两条线路+说明+当前勾选，外点/Esc 关闭，就地刷新列表），不跳转设置页；「立即更新」「切换至此版本」「卸载」等确认一律走 `app-confirm` 窗内确认卡（取消为默认、危险操作 danger 级），组件卸载/回滚同此。可启动 Windows 卸载程序 / 打开「设置 → 应用」移除本机应用（NSIS 单实例，不能并列多版本）。首页恢复动作（跳过用户插件启动/恢复完整插件）收进「恢复操作」行，仅在恢复上下文（启动失败/恢复板/粘性跳过）出现；slim 设置含「关闭时最小化到托盘」（`closeToTray`），slim 托盘 tooltip 中文且右键菜单顶部显示监管组件计数、首次隐藏弹出说明通知。
5. 导入 / 移除在曾停止内核时提示需在首页再启；boot 页 `shell:restart` 仍走 `retryFullPlugins`（清 skip）；启动器 `shell:retry-full-plugins` 走 `startDesktopFromLauncher({ recoveryLaunch, forceRestart })`。
6. 桌面端运行中（`ready|starting`）时首页主按钮为「关闭桌面端」，经 `shell:stop-desktop` 仅停内核并隐藏主窗，启动器保持打开。导入页「重新扫描」显示进度并保留勾选与会话分组折叠状态。
7. 桌面端「通用设置 → 启动时」与启动器「打开后自动启动桌面端」共用 `autoStartDesktop`：是则冷启动跳过启动器直进桌面（启动器经托盘右键）；否则先开启动器。待导入 / 更新确认 / 上次启动失败时仍先开启动器。

- 插件排查禁用/启用写盘后若内核在跑，只经 `startHarness`/`restartWithCleanup` 对齐，不得经 `startDesktopFromLauncher`（避免 `quitAfterStart` 关掉排查窗）。批量禁用可疑走 `shell:disable-plugins`（一次写盘 + 一次 align）。
- 「跳过用户插件」救生启动仍强制 ensure usage、dsh-im、market、dshbot；只跳过 session-search 和用户插件。dshbot 是桌面内置，任何启动都跑 `ensureDesktopDshbot`（先经 `removeLegacyDshbotPreset`/`stripBlockFromFile` 迁移旧受管残留），但仅在 `dshbotEnabled`（默认 false，界面设置「机器人（Bots）」开关控制，切换后自动重启 Harness）为 true 时写 overlay 挂载；为 false 时只删除 overlay、不做 vendor 校验、不 fail start。desktop-install 仍 required。可选桌面预置不得拖垮恢复通道。
- 桌面自有行只经 `--patch` overlay 挂载：install insert 在 `desktop-install.patch.yml`（**每次**启动传，全量 + skip），usage insert 在 `desktop-usage-panel.patch.yml`（**每次**启动传，全量 + skip），session-search 覆写在 `desktop-plugins/session-search/desktop-session-search.patch.yml`（仅全量启动传；`session-query-sqlite` `openAt: first-search` + 耐久 `dsh-home/session-query.sqlite`，产品语义归 mobile-remote 搜索），dsh-im insert 在 `desktop-plugins/dsh-im/desktop-dsh-im.patch.yml`（**每次**启动传，全量 + skip；产品语义归 remote-settings 卡），market insert 在 `desktop-plugins/dsh-market/desktop-dsh-market.patch.yml`（**每次**启动传，全量 + skip；产品语义归 marketplace-settings 卡），dshbot insert 在 `desktop-plugins/dshbot/desktop-dshbot.patch.yml`（仅 `dshbotEnabled` 为 true 时随**每次**启动传，全量 + skip；产品语义归 dshbot 卡）。full-start 的 argv 顺序固定为 install → usage → session-search → dsh-im → market → dshbot（dshbot 仅在 `dshbotEnabled` 为 true 时在列）。profile 的 `cordis.patch.yml` 纯用户所有——ensure 只 strip 遗留受管块（strip 后无内容须归一化回 `[]`，否则 CLI `parsePatchList` fail-loud），绝不写回；strip 与 overlay 写入在同一 ensure 调用内、每次 spawn 前成对发生（CLI insert 不按 id 去重，受管块残留 + overlay 同时组合 = 双挂载）。**绝不**把 `cordis.patch.yml` 传给 `--patch`——CLI 在 `--skip-user-plugins` 下仍应用 overlay，传整份用户层等于没跳过。
- Windows `.cmd` 外部 dsh（`shell: true` spawn）时 `harnessSpawnPlan` 必须给命令与所有含空白参数加引号——overlay 路径在 `AppData\Roaming\<用户名>` 下，用户名带空格是常态，不加引号参数会被 shell 拆开。
- 插件级恢复（归因、逐项/批量禁用、skip、恢复完整插件）**只**存在于启动器 Recovery Board 一处；boot 页只保留瞬时动作（重试 / 取消自动重启 / 下载日志）加「回启动器排查」跳板（`shell:open-launcher`，BOOT 角色发起时附带 show-tab home）。boot 页不得再长出自己的恢复操作副本。
- skip 只能救用户层（profile patch / manifest bundles）；模板 bundle 挂载的内置组件包（`DESKTOP_PACKAGES`）缺失属运行时损坏，`buildLaunch` 启动前探测并报可操作错误（源码运行 → `npm run setup:harness`；安装包 → 重装），不进入无效 skip 循环。探测覆盖「包不可解析」与「manifest 在但声明入口未构建」两种（与打包门禁共用 `missingDeclaredEntries` 判定）。
- skip compose 语义由打包门禁背书：after-pack 对打进 dist 的真实 CLI 跑 `dump-config` skip/full 双轮（`scripts/check-skip-compose-contract.js`，临时 DSH_HOME + 用户层 canary + 预埋受管块回放迁移）——skip 轮 canary 必须消失且 install / usage / dsh-im / market 四个桌面行仍挂载，full 轮 canary 必须回来并按 install → usage → session-search → dsh-im → market 顺序组合；session-search 只允许 full 轮出现。每个 always-on 桌面行必须各**恰好一次**（>1 = 受管块残留与 overlay 双挂载），迁移后 `cordis.patch.yml` 不得再含受管记号（install + dsh-im 两代块都回放）且 canary 用户行必须保留；任一违反即打包失败。单测层不能替代此门禁（单测 mock 了 dsh.start）。
- 启动器自有旗标（`--skip-user-plugins`、`--patch`）必须位于 CLI 语法前缀（首个未知 token 之前），否则被 CLI 当 app args 吞掉——桌面以为跳过、实际满载。`dsh.test.js` 从 vendored `args.ts` 的 web 子命令提取旗标集做语法行走断言，vendor 同步改语法会即刻红。
- Recovery Board 在 sticky skip、`lastStart.ok===false`、desktop error、genericCause、pluginTreeFailure 或存在 suspects 时于首页展开。
- 每个 `shell:*` IPC 都必须有 main 侧授权，「preload 没暴露该方法」不构成边界：中央 `registerIpc` 的 `handle` 对每条注册强制 `assertIpcSender(roles)`；不在 wrapper 内的注册点（`chrome.js` 的 `shell:window` / `shell:window-state` / `shell:chrome-metrics`、`pty.js` 四个 `shell:pty-*`、`preview.js` 的 `shell:preview-*`、`preview-file-window.js` 的 `shell:file-preview-state`）必须各自校验。`ipcSenderRole` 对已销毁 sender、非顶层 frame、缺 URL、URL 不属于该 role 的 sender 一律返回 `null`。原生浮窗（桌面宠物 / Live2D）走各自独立门禁，不在中央表内。
- Recovery Board 诚实化：suspect 命中 `DESKTOP_PACKAGES`、dsh-im 别名（`@xmanrui/dsh-im` / `dsh-im` / `xmanrui-dsh-im`）或 install overlay 路径记号（`desktop-plugins/install-dsh-plugin`）（精确名或子路径 specifier）**且不在 profile 插件清单** → 行标 `inBox`（badge「内置组件」）、payload `desktopRuntimeDamage: true`；verdict 换成「内置组件损坏：禁用/跳过均无效，重装安装包或 `npm run setup:harness`」，并压过 sticky skip 文案（skip 修不了运行时损坏）。inBox 行不进批量禁用集合。同名用户插件**在** profile 清单时仍是普通可禁用 suspect。
- `shell:stop-desktop`（启动器专用）取消 harness 自动恢复与在途 restart/start、停止 dsh 内核、清理 PTY/预览并销毁主窗；托盘在内核未运行时打开启动器；不退出 Electron 进程、不关启动器。
- 版本页 `listReleases` 附带 `installed`（运行模式、注册表 Setup 版本/路径、是否可卸载）；卸载优先 NSIS `Uninstall*.exe`，否则打开「设置 → 应用」；源码运行且无注册表安装时隐藏卸载按钮并给出明确说明。
- 导入重新扫描保留 session-rel / skill-id / plugin-name / mcp-id 勾选与会话分组折叠；扫描完成展示计数与时间戳。
