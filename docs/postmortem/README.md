# Postmortem（事故复盘）

事故叙事层——仓库里唯一允许讲故事的地方。决策记录写「为什么这样定」，feature 卡写「契约是什么」，这里写「当时怎么坏的、为什么所有检查都没拦住、之后加了什么防线」。

## 什么时候写

同时满足三条才值得一篇（上游标准）：

- **隐蔽**：缺陷在用户手里才暴露，或潜伏期很长；
- **系统性**：不是手滑，是流程/测试/设计上的洞；
- **昂贵**：排查或修复成本高，或影响面大。

普通 bug 在提交 / PR 中记录根因与行为验证即可，不强制建决定或复盘。反复出现时先区分旧缺陷回归、上次未闭环、相似症状和观察工具错误；补齐能发现旧故障的复现及 CI 接线，再判断是否需要长期策略调整。

## 格式

文件名 `NNNN-topic.md`（四位序数递增）。骨架：

```
# Postmortem NNNN: <标题>

## Executive summary
## Timeline
## Root cause
## Why every test / check missed it
## Guardrails added
## Lessons
```

`Guardrails added` 记录实际补上的行为复现、执行接线或真实环境验证及其落点；只增加文字规则不代表防复发。没有必要增加新门禁时，说明现有验证如何覆盖即可。`Lessons` 保留有证据支持的可复用结论。

只有新增长期取舍时才更新已有决定或补一篇记录并互链；不把复盘再复制成决定。
