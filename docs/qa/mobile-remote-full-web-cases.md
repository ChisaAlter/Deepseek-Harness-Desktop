## 0. 生产交付标准

### 0.1 完成与可交付（对抗性修订）

- **测完全功能** = 本表全部 P0 都有结果（Pass / Fail / Blocked / N/A(轨) / N/A(前置) / Deferred），**且每个 Blocked / N/A(前置) 都写了已尝试的夹具步骤**。
- **可交付（本轨全功能通过）** = 无 Fail **且无未豁免 Blocked**。Blocked 不是绿：每条 Blocked 必须有书面原因 + 产品负责人豁免栏，否则报告只能写「未完成」。
- **N/A(轨)**：该用例属于另一轨（如 T1 外出条在 LAN 场）。填 N/A(轨) 不计本轨缺口，但报告必须写明该轨未测，不得宣称 T1。
- **N/A(前置)**：产品当场没有该对象（如无 open PR）。必须先执行本表夹具（§F）再填；跳过夹具直接 N/A = 无效。
- 没有任何白名单：**每一个 P0 同权**。不存在「测了这几条就算全量」的短清单。

### 0.2 对照规范化（禁止裸字符串比 chip）

两端文案本来不同（手机 chip `grok-4.6`，桌面 aria `选择模型，当前 grok-4.6，推理等级 Default`）。对照一律抽**规范化字段**：

| 域 | 抽什么 | 一样的定义 |
| --- | --- | --- |
| 模型 | provider id + model id + reasoningEffort（手机：chip 主文案+档位；桌面：ModelSelect aria 里「当前 X，推理等级 Y」） | 三元组相等 |
| 权限 | 预设名（只读 / 工作区写入 / 完全访问） | 同名 |
| 会话集合 | sessionId 集合（能取 id 用 id；截图场用标题全文，但报告注明「按标题」） | 集合相等 |
| 当前会话 | sessionId | 相等 |
| 消息 | 最新用户句原文 + 该轮助手正文（工具卡允许折叠） | 原文相等 / 正文语义同一段 |
| Git | isRepo、refName、ahead/behind、hasChanges、主按钮 **label**（两端同为 `resolveGitQuick` 表英文） | 同状态同 label |
| 归档 | 归档 sessionId 集合 | 集合相等 |
| 审批 | pending 有无 + 命令/工具名 | 同有同无、同名 |
| 工作区 | path 列表 | 集合相等 |

**允许不一样（备注写明，不许装对齐）：** 单栏 vs 四栏几何；Files/Diff 写、Stage、PTY、Browser、MCP/技能写、市场、壁纸（冻结/NEVER）；手机藏 blank/dshbot（故意）；手机本地外观主题。

### 0.3 证据纪律

- 改状态类 P0：**成对**手机+桌面截图（同分钟）+ 抄 sessionId / refName。只有 SPA 截图 = 该条无效。
- 截图与报告不得出现完整 `#offer=`、API 密钥。
- 每条按 live-acceptance §0.5 格式记录；本表 §17 只做汇总，不代替逐条记录。

| 轨 | 可交付 | 客户端 |

## 1. PAIR 配对与连接（P0 = 15）

**桌面对照：** 侧栏远程弹窗（origin、中继灯、复制、刷新）；Harness 进程。

### PAIR-001 · 外出二维码 origin 与切面 · P0 · T1 · 主
- **前置：** 桌面远程=外出；中继已连接。
- **步骤：** ① 弹窗复制链接，只抄 origin+path；② 手机拉该 origin 的 `index.html`+`app.js`。
- **期望：** `http://125.124.85.212:3389/dshd`；`app.js` 无 `fetchAgents`/`createAgent`，含 host `session.list`；链接不含 `:3180`/`:8411`。
- **桌面抄录：** 弹窗 origin=____。必须一样。

### PAIR-002 · 局域网 origin 与停听 · P0 · T2 · 主
- **步骤：** ① 模式=局域网，抄弹窗 origin；② 手机开 `http://<LAN>:3180/`；③ 桌面关远程，再请求。
- **期望：** ② 落地本机 SPA；③ 拒连（不听）。
- **桌面抄录：** origin、关闭后端口状态。必须一样。

### PAIR-003 · 中继未连接闸门 · P0 · 每轨 · 失败
- **步骤：** 中继断开时打开弹窗。
- **期望：** 只有状态文案；无二维码、无复制、无刷新。
- **对照：** `[data-dsh-remote-qr]` 闸门与卡不变量一致。

### PAIR-004 · 刷新配对码 · P0 · 每轨 · 主
- **步骤：** ① 抄当前码指纹（长度/前 8 字符即可，勿存全文）；② 点刷新；③ 用**新**码配对；④ 用**旧**码再试。
- **期望：** 新码可配对；旧码行为明确（拒绝或按 TTL），不得静默成功又失败。
- **桌面抄录：** 刷新前后码指纹。

### PAIR-005 · 局域网↔外出切换 · P0 · 主
- **步骤：** 桌面切模式，立即看弹窗。
- **期望：** origin 立刻变为对应轨（`:3180` ↔ 公网 `/dshd`）；不残留旧码。
- **桌面抄录：** 切换前后 origin。必须一样。

### PAIR-006 · 系统相机扫码 · P0 · T1/T2 真机 · 主
- **步骤：** 系统相机扫当前模式二维码。
- **期望：** 浏览器打开完整 URL，自动进对话壳；不是官方四栏。微信/QQ 内打开＝本条 Fail（换系统相机或粘贴重测）。

### PAIR-007 · 粘贴完整 URL · P0 · 每轨 · 主
- **步骤：** 连接页粘贴完整配对 URL → 用链接连接。
- **期望：** 与扫码同等进 chat；随后 LIST-001 过。

### PAIR-008 · 残缺链接 · P0 · 失败
- **步骤：** 粘贴无 `#offer=` / 截断的 hash。
- **期望：** `#connect-error` 明文；不假装已配对；桌面无新配对设备。

### PAIR-009 · 过期 token · P0 · 失败
- **步骤：** 用 PAIR-004 里作废的旧码（或过期 offer）连接。
- **期望：** 明文错误；可返回粘贴重试。

### PAIR-010 · sticky 无 hash 重连 · P0 · 主
- **步骤：** 配对成功后关标签 → 开同 origin 无 hash。
- **期望：** 自动重连进 chat；LIST-001 重新成立。

### PAIR-011 · 跨 origin sticky 隔离 · P0 · 边界
- **步骤：** 在公网 `/dshd` 配对后，开 `:3180`（或反向）。
- **期望：** 不继承登录；各自独立 sticky。

### PAIR-012 · 已保存的电脑 · P0 · 主
- **步骤：** 无 hash 打开，有多台/一台已存时看 `#saved-computers`。
- **期望：** 列出该机；点选可重连到**同一 daemon**（serverId 一致）。

### PAIR-013 · 忘记 · P0 · 主
- **步骤：** 点「忘记」→ 关开标签无 hash。
- **期望：** 不自动连；该机从列表消失；桌面配对能力不受影响（重新扫码可回）。

### PAIR-014 · 断开这台设备 · P0 · 主
- **步骤：** 设置 → 断开这台设备。
- **期望：** 回连接页；本机 sticky 清空；桌面远程仍开、其它设备不受影响。

### PAIR-015 · Harness 未起（造障，须批准）· P0 · 失败
- **前置：** 执行人书面同意停 `dsh web`。
- **步骤：** ① 停 Harness；② 手机刷新/重连；③ 恢复 Harness；④ 再看抽屉。
- **期望：** ② 明文「桌面端未启动」类错误，**不是**空「新会话」列表；④ LIST-001 恢复。

**PAIR P1：** 连接页「扫描二维码」按钮能力与降级提示；无摄像头权限出权限页+改用粘贴；中继断片刻横幅不卸配对（DISC 也覆盖）；同 origin 两个标签同 sticky 并存不互踢；PAIR-016 APK 应用内扫 = **Deferred（T3）**。

## 3. LIST 会话列表（P0 = 12）

**抽数规程（LIST-001 前必读）：** 桌面展开全部工作区 +「展开其余 N」直到无折叠；D = 活会话行标题（不含 blank、不含工作区头；子智能体行单独列 D-sub）。手机抽屉展开全部头、滚到底；P 同规则、P-sub 单独列。能拿 id 优先按 id 比。

### LIST-001 · D = P 集合相等 · P0 · 主
- **步骤：** 按规程抄 D / D-sub 与 P / P-sub；截双端图。
- **期望：** D=P 且 D-sub=P-sub；任何缺/多/标题不等 = Fail（禁止写「31/33 还行」）。

### LIST-002 · 打开桌面当前选中行 · P0 · 主
- **步骤：** 桌面选中某正式标题会话；手机点同名行。
- **期望：** 同一 sessionId；手机标题栏 = 该行标题；时间线非空白 hero（除非桌面本来 blank）。

### LIST-003 · 反向：桌面动列表 · P0 · 反向
- **步骤：** 桌面新建一条会话（任一仓）。
- **期望：** ≤30s 手机列表出现该行（集合跟随）。手机**当前打开的会话不被动切换**——如被切走记 Fail。

### LIST-004 · 分组头与成员 · P0 · 主
- **期望：** 头 = `workspace.list` 的 path/title；每夹成员 = 该 workspace ∩ L；无用户自建「文件夹」控件。

### LIST-005 · 折叠/展开 · P0 · 主
- **步骤：** 折叠再展开两个头。
- **期望：** 成员不丢、顺序不变，仍 = 桌面。

### LIST-006 · blank 隐藏 · P0 · 空（故意不一样）
- **期望：** 桌面 blank New Session 槽不出现在手机活列表；过滤后为空也不得画假「新会话」行。

### LIST-007 · dshbot 隐藏 · P0 · 空
- **期望：** `origin:'dshbot'` 行手机不出现（无此类数据填 N/A(前置)+说明查过）。

### LIST-008 · 全量无假分页 · P0 · 边界
- **期望：** 无「加载更多」；桌面「其余 N」那 N 条手机一次可滚到。

### LIST-009 · 子智能体折叠+只读 · P0 · 主（F-SUB）
- **期望：** 缩进折在父下、标注子智能体；打开无发送键，有只读说明（=桌面子会话行为）。

### LIST-010 · running 状态点双向 · P0 · 主+反向
- **步骤：** ① 手机发一轮，桌面看该行；② 桌面发一轮，手机看该行。
- **期望：** 两个方向 running 标识都出现、结束后消失。

### LIST-011 · 列表加载失败 · P0 · 失败
- **步骤：** 借 PAIR-015 造障窗口或断隧道瞬间刷新抽屉。
- **期望：** 明文「无法加载会话：…」；不是空列表装已对齐。

### LIST-012 · 工作区头文案 · P0 · 主
- **期望：** 头名/路径与桌面一致；不是 HTML 写死产品名。

**LIST P1：** 「一个列表」平铺=L、切回不丢；超长标题前 8 字+sheet 全文；桌面拖动**工作区顺序**（`workspace.insertBefore`）手机跟随；行打开即 CHAT-004 复用。
