# 桌宠窗口区域验收

日期：2026-09-29。范围：`desktop-live2d-pet`。

## 复现与修复

新增测试在修复前失败：角色与聊天卡之间的空隙被 `overPet` 判成可交互；真实管理器未设置任何原生区域。修复后定向测试 98/98 通过。

原生区域仍使用单显示器坐标，但只保留各绘制源的矩形；鼠标命中也按分离表面计算。显示窗口不激活，仅显式聊天取焦点。

## Windows 实机

`verify.cjs` 使用真实 Electron 管理器、THA4 页面和独立临时配置，不读取或修改用户配置。`probe.ps1` 查询 HWND 区域并产生真实鼠标事件。

- 100% 与 150% 缩放：模型初始化后能绘制；启动不抢焦点。
- 真实鼠标按下、移动、松开：角色移动约 80 DIP，原生区域裁切不破坏拖拽。
- 状态卡与聊天卡保持可见；截图见 `panel.png` / `chat.png`。
- 聊天卡显式开启后可输入，主窗可重新取得焦点；测试下层页面持续绘制。
- 150% 最终强化检查：渲染器暂停更新，主进程交互状态故意保持 `true`，两个独立区域之间的真实点击仍到达下层页面；点击后状态仍为 `true`，证明穿透由原生区域保障。
- 零面积区域的 Win32 类型为 `NULLREGION`，不是恢复整窗。最终数值见 `results.json`。

运行时须从仓库根目录启动，移除环境变量 `ELECTRON_RUN_AS_NODE`，用仓库 Electron 执行 `docs/qa/results/2026-09-29-pet-window-regions/verify.cjs`；可追加 `--force-device-scale-factor=1.5`。脚本短暂操作鼠标及测试窗口，成功后恢复鼠标位置并退出。

## 其他门禁与限制

治理 6/6、文档同步 7/7 通过。窗口动效脚本 `node scripts/run-window-motion-qa.mjs --composed --evidence-dir=docs/qa/results/2026-09-29-pet-window-regions/window-motion` 通过主窗与启动器的四角桌面合成检查及原生窗口状态检查；可见 DWM 插值仍不能仅凭状态检查认证。

一次全量测试在并行实机负载下出现人格重试计时与启动器缩放时序失败；两文件隔离重跑 44/44 通过。首次 150% 实机脚本达到 60 秒截止，扩展诊断期限后最终通过。最终独立全量 `npm test`：2838 项，2836 通过、2 跳过、0 失败（143.7 秒）。

macOS 原生区域隔离未覆盖。实机下层页面是可计数的测试页；此证据确认交互、焦点与渲染连续性，不证明截图提及的所有 Harness 页面加载故障均具有相同根因。
