# Decision: 用量统计紧凑月历与会话修复身份

Status: implemented

中文 | [English](2026-09-23-usage-calendar-repair.en.md)

## Problem

设置面板宽度约 520px 时，旧热力图以「周为列、星期为行」且列宽弹性铺满，31 天会膨胀成约 90px 的日方块，竖向延伸到视口外。月份只能前后翻，不能指定日期范围。

修复 RPC 把扫描返回的会话 ID 限为十六进制与连字符，但实际桌面会话还有 `session-whale-<uuid>`；请求在定位工件之前就被拒绝为 `invalid session id`。

## Decision

- 热力图改为固定 24px 日格的月历，星期为列、周为行；月份用设置页现有 `SettingsSelect`，UTC 起止日期用 `Input`，显示所选日期的 Token 和活跃天数。筛选只作用于这张月历；全历史 KPI、会话排行与另一张独立的每日图沿用各自原有统计范围。
- 修复 RPC 接受本轮扫描明确列入失败名单的安全单路径身份，放弃十六进制假设。工件定位先匹配完整持久化 ID，再兼容旧调用者提供裸 UUID 的 `session-` 目录。
- 只修复名单中的会话，备份、最高 canonical 代与原子替换合同不变。

## Alternatives considered

- 保留可伸缩周列，只限制卡片高度：日格仍随宽度变大，且滚动会隐藏日期上下文。
- 只放月份箭头：无法指定真实日期范围。
- 修复时继续维护允许的 ID 前缀列表：新插件前缀仍会复现同一错误。

## Consequences

筛选控件只覆盖热力图的 182 日数据；其他总量口径不被误改。修复入口与真实扫描身份绑定，避免任意 RPC ID 触及日志。月历需要在窄设置页和深色主题下分别检查。

## Verification

`session-whale-<uuid>` 与裸 UUID 工件可定位；未标记失败或含路径分隔符的 RPC ID 被拒绝。月历在窄设置面板不产生大日格或横向溢出；日期控件只在最近 182 个 UTC 日内筛选，月度汇总随选择更新。
