# Decision: 远程入口收束到账户菜单

Status: implemented

中文 | [English](2026-09-23-remote-account-menu.en.md)

## Problem

官方账户菜单接管设置入口后，桌面侧栏底部仍单列「远程」。设置与远程都是低频的桌面配置动作，分置两行使底部导航变长。远程行已拥有配对、设备管理和 QR 闸门，移动入口时不能复制弹窗实现或改变配对协议。

## Decision

- `ui-settings-account` 在账户菜单内声明可选的 `settings.launcher.action` 子槽位；`ui-settings-remote` 只有在桌面预加载提供完整远程 API 时贡献「远程」菜单项。菜单项沿用现有菜单原语与手机图标，打开远程插件原有配对弹窗。
- 账户入口存在时隐藏独立远程行；账户入口缺席时保留原侧栏远程行。两条路径共用远程组件和桌面 API，避免装配顺序或账户插件缺席时失去配对入口。
- 远程弹窗关闭后焦点返回账户按钮；配对状态、二维码显示条件、设备操作及设置页高级选项保持原有来源。

## Alternatives considered

- 将账户菜单的「远程」直接跳到设置页可以少改组件，但用户还需在设置中寻找二维码，改变了原入口的一步配对路径，故拒绝。
- 账户插件直接调用远程预加载 API 并复制弹窗可以绕过槽位，但会让账户插件拥有远程业务逻辑，后续两份配对界面容易分叉，故拒绝。
- 无论账户菜单是否存在都保留独立远程行最简单，但没有完成入口收束，故拒绝。

## Consequences

账户菜单需订阅子槽位条目，远程插件需在菜单与侧栏回退之间切换注册。两种装配顺序、账户缺席、远程 API 缺席、弹窗关闭焦点须纳入定向测试；[账户入口卡](../../../features/account-settings-entry.md)和[手机远程卡](../../../features/mobile-remote.md)记录现行路径。
