# Decision: 桌面直接进入工作区

Status: implemented

中文 | [English](2026-09-29-direct-desktop-entry.en.md)

## Problem

用户要求跳过 DeepSeek 原版首次欢迎页，直接进入桌面端。此前[桌面桥接](../architecture/2026-09-26-upstream-desktop-bridges.md)与[欢迎页资源修复](../bug-fix/2026-09-29-welcome-resource-closure.md)保留的凭据入口门禁不再符合产品路径；退出账号和凭据失效也会重开欢迎窗。

## Decision

取消主进程欢迎窗创建、工作区延迟回调及退出/过期回流。启动器与 boot 恢复流程不变，Harness 就绪直接揭示工作区。账号观察与语言读取在后台初始化，不读凭据决定能否进入；保留设置登录、授权链接外开与 Platform 身份刷新。不写虚假密钥、不伪造已登录状态、不修改用户设置。

冒烟不再自动点击 API Key/稍后设置；检测到任何原版欢迎窗立即失败。保留欢迎资源及独立渲染测试作为非入口资源，不再将其通过描述为首次启动验收。

首次使用的用途/过程设置引导同样不自动出现：可信主 frame preload 在 `dshDesktop` 提供 `onboarding: false`，账号插件据此不创建引导 controller 或 overlay。缺省能力仍保留上游行为，不影响其他壳；不篡改历史偏好或引导进度。通用设置与账号入口保持可用。冒烟删除自动点击继续/稍后配置逻辑，根节点 inert 或阻塞对话框持续存在时失败。

## Alternatives considered

自动调用欢迎窗 skip：仍创建并可能闪现窗口，继续让测试掩盖入口偏差，拒绝。

将首次设置持久化为已完成：会改动用户数据，且可能触发 controller 写入默认偏好；改用渲染前能力退出，不创建引导。

清空所有账号集成：虽然去掉欢迎窗，但破坏设置登录、系统浏览器授权及 Platform 页面，拒绝。

## Consequences

无凭据可进入工作区，但使用模型前仍须在设置中完成配置。入口、退出/过期与后台账号初始化有定向回归；隔离源码冒烟覆盖无凭据启动。安装包构建保持暂停，已安装旧包不会因此自动更新。
