# Decision: Journaled import transactions, protected interval, and launcher audit remediation (F1–F10)

Status: implemented

[中文](2026-09-28-import-transaction-and-launcher-remediation.md) | English

## Problem

Subsequent file-import, recovery-cancellation, and installation-rollback defects are addressed in [closeout audit fixes](2026-09-28-launcher-audit-closeout-fixes.en.md). This decision's directory transactions and maintenance slot remain in force.

A comprehensive launcher audit (Codex with ChatGPT joint review; report at `docs/qa/results/2026-09-28-launcher-audit/REPORT.md`) confirmed: attachment import deleted destination-only files under `overwrite=false`; directory replacement was not crash-safe (dest removed before staging rename, recovery deleted the only surviving copy); the import bypassed task protection by calling `dsh.stop()` directly; same-named skills from different roots silently overwrote each other; the slim "restore full plugins" path never cleared the sticky skip flag; `waitForInstall`'s same-version shortcut reported cancelled/failed installs as installed; attachment failures did not affect `ok`; the import IPC had no `catch` so errors went silent; `--dsw-alias-layer-fill-2` was undefined so dialog/popover backgrounds broke; and the tablists/radio groups lacked keyboard navigation and ARIA wiring.

## Decision

1. **Journaled three-stage replacement (F2)**: new `src/main/import-transaction.js` — `replaceDirJournaled`/`commitStagedDir` run staging→journal(`staged`)→dest→bak(`replacing`)→tmp→dest(`committed`)→drop bak. Recovery reconciles journal state and **never deletes** unjournaled `.import-tmp`/`.import-bak` dirs (possibly the only surviving copy); they are reported `pending` and put the journal into `blocked`, which blocks further imports.
2. **Attachment merge (F1)**: `mergeDirJournaled` copies dest into staging then overlays source; `overwrite=false` keeps same-path dest files, `true` replaces; destination-only files survive both modes.
3. **Explicit same-destination skill rejection (F4)**: `collectSkills` tags `sourceCollision`; `importSkills` groups the selection by canonical destName before any write — multiple distinct sources for one dest → `failed/ambiguous-destination` with zero writes; `overwrite` does not resolve ambiguity.
4. **Protected quiescence interval (F3)**: `runImportTask` runs "stop kernel → runImport" inside the task-protection nonterminal `coordinate('stop', {preConfirmed:true, commit})`, holding the Host admission lock for the whole copy; `startDesktop`/`startSkippedOp`/`retryFullPlugins` return `import-in-progress` during import; an empty selection takes the task slot but writes nothing and does not stop the kernel. Slim fails closed for nonempty imports (`slim-import-unsupported`); a `blocked` journal rejects new imports (`import-recovery-blocked`).
5. **Slim sticky-recovery clearing (F5)**: `retryFullPluginsSlim` stops the external desktop → strictly reads the desktop `config.json` → resets only `pluginRecovery` to the empty shape while preserving `disabledPlugins` and unrelated keys → atomic write → re-read verification → single launch; any failure refuses without spawning.
6. **Install bound to the requested version (F6)**: `waitForInstall(child, baseline, signal, onProgress, deps, targetVersion)` succeeds only when the registry version exactly matches the requested version and the exe exists; the same-version timeout shortcut is removed.
7. **Attachment failure in the overall result (F7)**: `importSessions().ok` requires no session `failed` and `attachments` not `failed:*`; `runImport().ok` inherits it; the summary appends `共 N 项失败`.
8. **IPC terminal diagnostics (F8)**: the import button gains `catch`/`finally` control recovery, an `importOpSeq` guard against late events overwriting the terminal result, explicit swallowing of `cancelImport` rejection, actionable copy when the bridge is absent, and `role="status" aria-live="polite"` on `#import-result`.
9. **Token and typography (F9+UI)**: `--dsw-alias-layer-fill-2` → `--dsw-alias-bg-layer-2` (confirm card, route popover); `.import-scope-detail`, `.import-toolbar`, `.import-foot-opts`, `.import-foot-run` normalized to `12px/18px`; `.row-title` gains ellipsis.
10. **Keyboard and semantics (F10)**: main nav `aria-orientation="vertical"` + roving tabindex + ↑/↓/Home/End + Enter/Space manual activation; import categories horizontal equivalent; tab `id`/`aria-controls` and panel `aria-labelledby` fully wired; `route-seg`/`route-picker` get `role="radio"`/`aria-checked`/arrow keys skipping disabled items; the existing `alertdialog` focus, Escape, and Tab loop are preserved.

## Alternatives considered

- **Copy attachments file-by-file directly into dest without staging**: a crash leaves a half-merged live tree with no transaction record; staging + the shared transaction keeps one recovery model and never exposes a partial result.
- **Keep the legacy "delete `.import-tmp`" recovery**: that is the root cause of F2 — the staging dir may be the only surviving copy; conservative preserve-and-block beats data loss.
- **Introduce a cross-process locking protocol so slim can import**: out of scope and unverifiable here; fail-closed is an explicit safety boundary already surfaced in the UI.
- **F4 silently prefer one root (e.g. home wins)**: silent choice may still overwrite the package the user meant; explicit rejection costs one extra click.

## Consequences

- Every failure point keeps ≥1 intact copy (dest or bak); a `blocked` journal requires manual handling before re-import, and recovery is idempotent/repeatable.
- While new-format txn journals/backups exist, the code must not roll back to the legacy cleanup; roll back code only after disabling imports, quiescing, and reconciling open transactions.
- F6's real Windows installer behavior still needs a one-off disposable-environment check (mocked coverage done).
- Tests: `data-import` + `import-transaction` + `ipc` 103/103; fault injection `.tmp-qa/c2c_plan1/verify-fixes.cjs` 16/16; full suite 1884 pass (7 failures are pre-existing vendor-tree items).

## Iteration-2 review corrections (GPT acceptance R1–R8)

GPT's independent review of iteration 1 returned `VERDICT: CHANGES_REQUIRED` (3×P1 + 5×P2). The corrections below amend iteration-1's overstatements:

4. **R4 install target binding**: `installRuntime` freezes `targetVersion` (preferring `info.tag` minus the `v` prefix to keep prerelease identity) and `waitForInstall` drops the "empty target accepts any changed version" fallback — an empty target fails closed; a same-version request now requires the exe mtime to exceed the baseline stamp (or a new exe to appear when baseline had none) instead of succeeding on the first poll.
5. **R5 ambiguity preflight**: `runImport` groups `selectedSkillIds` by canonical destName (Windows case-equivalent) before any write, refusing `ok:false`+`ambiguous-destination` with zero writes across sessions/attachments; colliding skill rows render a `同名冲突` badge with the conflicting sources in the UI.
6. **R6 slim retry slot**: `retryFullPluginsSlim` reuses the single `importAbort` slot, so concurrent retry/retry, retry/Start, and retry/import refuse rather than double-spawn across the whole stop→config→launch sequence.
7. **R7 persistent operation-scoped diagnostics**: selection counts moved out of `#import-result` to a dedicated `#import-selection-line` so a rescan or selection change cannot overwrite the terminal summary; `summarizeImport` renders `result.error` with actionable copy (slim/recovery/ambiguous/needs-recovery/shutdown/in-progress), counts `credentials` in `totalFailed`, and lists item-level failures (cap 8); every progress event carries `op` (a renderer-issued `opId` echoed via `options.opId`), and the handler drops events from a stale op; `cancelImport` rejection now surfaces actionable text instead of being swallowed.

## Iteration-4 review corrections (GPT re-review — shared maintenance slot + full admission)

GPT's third verdict closed R5, downgraded R1/R2 to PARTIAL, and kept R3/R4/R6/R7/R8 open. Root cause: the earlier "single slot" was only held on the import side — install/start/retry merely CHECKED it instead of ACQUIRING, which is one-way exclusion, not mutual exclusion; several start/write surfaces also bypassed admission entirely. Iteration 4 upgrades it to a shared maintenance slot and closes the admission coverage:

1. **R1 unreadable journal fails closed**: `readImportJournal` now distinguishes `ENOENT -> null` (no transaction) from other read/parse errors -> `{unreadable:true}` (must block). New `journalIsBlocked` (`phase==='blocked'` or `unreadable`) is the shared verdict used by `launcher-service`, `index.js`, and `launcher-gate.js`; the attachments import path is gated on `sessionsNeedRecovery` too; a sweep subdirectory read failure is reported pending rather than silently skipped.
2. **R2 real filesystem boundary + op inventory**: `txnPathsOwned` gains `canonicalParentChain`/`isInsideCanonical`/`parentChainIsLinkFree` — a journal `dest` must resolve inside the canonical parent chain with no symlink/junction on the chain, closing the "lexically inside but escaping the sweep root via a link" bypass; the `commitStagedDir` outer-catch journal write is now guarded; both reconcilers accept `allowedOpIds` (the opId inventory the importer registers in `journal.txnIds`) and report `unregistered-journal` pending instead of following a foreign journal's rename/delete plan.
3. **R3 start/write surfaces join admission**: `shell:restart` (`restartWithCleanup`) checks `importGuard.isMaintenanceHeld()` BEFORE `taskProtection.coordinate` — a held slot returns `code:'maintenance-in-progress'` without ever raising a misleading "confirm to proceed" dialog; `cleanupDesktopResources` changed from fire-and-forget to returning a Promise, and all three restart/reload/quit commits now `await preview.closeAll()`; `shell:save-config` (`applyRendererConfigPatch`), `shell:saveLauncherConfig`, and the `profile-ops` `disablePlugins`/`enablePlugin`/`removePlugin` all join `importGuard`/`journalIsBlocked` admission.
4. **R4 truthful waiting semantics**: `waitForInstall` checks `signal.aborted` before polling — an already-aborted signal returns `'aborted'` immediately instead of idling to timeout; the same-version-registered branch now `finish(null)` -> `waiting` the moment the installer child has exited and the exe stamp did NOT advance, instead of polling a dead installer's stale timestamp as if it could still complete.
5. **R6 bidirectional shared slot**: new `src/main/import-guard.js` — a module-level single owner token (`acquireMaintenance`/`releaseMaintenance`/`isMaintenanceHeld`/`maintenanceOwner`/`assertMaintenanceFree`; `releaseMaintenance` only honors the live owner token, so a stale handle cannot drop someone else's ownership). `runImportTask`/`installRuntimeOp`/`installUpdateOp`/`installReleaseOp`/`startOp`/`startSkippedOp`/`retryFullPlugins` all `acquireMaintenanceSlot(kind)` and release in `finally` — install/start/retry moved from CHECKING the import slot to ACQUIRING the same slot, giving true mutual exclusion in either arrival order.
6. **R7 cancel scoping + progress ownership**: the renderer's `cancelImport` snapshots `activeImportOpId` into `cancellingOpId` before awaiting — no longer reading shared state the run handler may have cleared mid-await — and surfaces a resolved `{ok:false}` refusal (`not-current-operation`/non-import owner); the `onImportProgress` filter tightened from "drop only a mismatched `op`" to "`payload.op` must equal the active opId" — an event with no `op` field is unowned and rejected too, so an unrelated emitter cannot overwrite the terminal state.
7. **R8 route-save serialization**: `issueRouteSave` resets `lastIssuedRoute` back to `selectedRoute()` on failure — it no longer points at an un-persisted value, so re-picking the same route is not deduped away; `pickDownloadRoute` (shared by radio and popup) now goes through the same `issueRouteSave`/`routeSaveGen` generation and only fires `afterSave` on a successful save — both control paths share one marker and one generation, eliminating popup<->radio ordering divergence.

**New tests**: `src/main/import-guard.test.js` (slot mutual exclusion / stale token cannot drop ownership / profile writes refuse under a held slot), plus the "failed save resets the issued marker so retry works" regression in `launcher-behavior.test.js`.
