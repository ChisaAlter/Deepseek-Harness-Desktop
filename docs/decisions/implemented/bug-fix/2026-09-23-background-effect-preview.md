# Decision: 背景特效预览复用画布规则

Status: implemented

中文 | [English](2026-09-23-background-effect-preview.en.md)

## Problem

「背景特效」弹窗的预览曾是固定的三层圆形渐变，只读取配色，不读取速度、光斑数量或形态。接入真实光斑后，弹窗又把每次父组件渲染新建的 `values` 对象列为草稿重置依赖：无关的主题状态发布会把刚选的速度、数量和形态覆盖回旧值。用户在弹窗里看到的仍可能是光球，也无法可靠保存草稿。

## Decision

弹窗用独立的预览 ID 绘制五个 `[data-blob]`，与固定画布共用 `wallpaper.css` 的几何、形态和动画选择器。草稿把配色、速度、数量、形态直接写到预览 DOM；速度、数量或形态编辑将方案标为自定义。弹窗只在关闭后重新打开时从最新持久值初始化草稿，开启期间的父组件重渲染不覆盖编辑。预览的模糊半径在小画布内缩小，四种形态仍使用同一组关键帧；保存一次性写入 Host，取消不落盘。

## Alternatives considered

- **维持静态预览并只显示配色** — 结构简单，但标题和功能契约承诺实时预览，形态与数量变化仍无法判断。
- **为弹窗复制一套形态 CSS** — 可独立调节小画布，却会让四种形态和动画在两处维护，再次产生预览与实际画布不一致的风险。
- **每次父组件更新都同步持久值到草稿** — 可反映外部修改，但设置弹窗中的未保存编辑会被无关主题更新清除；保存或取消才是明确的同步边界。

## Consequences

预览 DOM 多五个光斑，且同一份 CSS 选择器覆盖两个独立 ID；更改形态规则时只需维护一份。定向 UI 测试锁定草稿到 DOM 的传递及无关主题发布期间的保留，Electron 43 样式计算确认光球、极光带、混沌、光束产生不同背景与动画时长。弹窗开启时外部对同一组背景特效字段的写入不会自动覆盖草稿；再次打开才读取新值。主画布的持久化、壁纸优先级及减弱动效规则保持原契约。
