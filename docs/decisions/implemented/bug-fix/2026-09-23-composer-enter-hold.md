# Decision: 草稿发送稳定等待与合成层位移

Status: implemented

中文 | [English](2026-09-23-composer-enter-hold.en.md)

## Problem

首次发送把输入卡暂留在草稿位置，等待会话结构稳定后再滑到底部。用于抵消布局漂移的 `--dsh-composer-enter-offset` 写在被观察的输入区内；`MutationObserver` 把这次样式写入也当作外部结构变化，重置 80ms 静默计时。布局变化越多，输入卡越可能等到 450ms 上限才启动。放行后的相对定位 `top` 动画每帧仍要在主线程重算布局；有界面浏览器在滑行尾段实测出现 33/52/100ms 绘制空档和约 40px 的末段跳动。

## Decision

输入区仍观察会话结构变化和尺寸变化，以便保持草稿位置并延后滑动；观察器忽略输入卡栈自身的 `style` 属性变化。实际子节点或外部布局变化仍延长静默期。放行后只对首次发送的输入卡栈做 `transform: translateY()` 动画，让合成层独立推进；结束或取消时清除 transform。内置 fixed 浮层通过页面 portal 挂载，Hero 静止布局不使用 transform；减少动态效果直接落位。

## Alternatives considered

- **取消发送后的停留** — rejected：转录挂载和运行态控件仍会与逐帧定位动画竞争主线程，重现中途突跳。
- **只保留 450ms 固定延迟** — rejected：无结构变化时也要等待完整上限，增加发送后的无响应感。
- **继续用 `top` 并延长静默期** — rejected：回复启动与后续投影仍可能发生在滑行期，布局动画无法避开这些主线程工作。

## Consequences

自身的钉位样式不再延迟滑动，真实布局变化仍可使用最多 450ms 的稳定窗口。合成层位移降低主线程工作打断滑行的影响；该栈在动画期间短暂成为 fixed 后代的包含块，因而内置 fixed 浮层须保持页面 portal。定向测试在静默期后半段写入自身位移样式，真实浏览器检查位移轨迹、浮层与减少动态效果。
