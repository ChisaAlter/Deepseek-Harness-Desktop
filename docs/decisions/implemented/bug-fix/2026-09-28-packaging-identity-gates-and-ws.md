# Decision: 打包实例门禁恢复与账户运行时依赖补齐

Status: implemented

中文 | [English](2026-09-28-packaging-identity-gates-and-ws.en.md)

## Problem

0.3.3 发布预检复现三个装配门禁缺陷：同源实例无法收拢时被当作可接受重复，字节相同的不同源实例被允许合并，仅删除副本的成功收拢却因复制计数未增加而被拒绝。真实模块状态反例证明前两种布局分别破坏共享和隔离。另发现主进程账户启动链加载 `ws`，但根生产清单、锁文件和 asar 均未包含它，本机额外安装掩盖了缺失。

记录审计：[局部回退决定](../architecture/2026-09-24-whale-performance-partial-rollback.md) 已规定身份错误必须阻断，本次恢复其门禁而不解除实际布局阻断；[清单契约](../../proposed/bug-fix/2026-09-19-desktop-manifest-runtime-contract.md) 保留字段完整性的理由，本次补一项运行时闭包缺口；[插件复用](../../proposed/process/2026-09-22-packaging-plugin-reuse.md) 的深度闭包复用与本次模块身份判定不同，不被取代。用户在审查后明确要求修复上述三项及 ws 清单、锁文件。

## Decision

1. 任意两个不同源实例映射到同一目标实例均失败，文件相同不再豁免；无法收拢的同源拆分也必须失败，并输出来源、目标和收拢条件。
2. 收拢删除和孤儿清理都算作依赖树变化；清除相关文件、依赖图和已访问缓存后进入下一轮复验，不以复制数量为唯一进展信号。十二轮上限保持不变。
3. 根生产依赖显式声明并锁定 `ws@8.21.3`，与本机已用版本一致，不更改其他锁定版本。可选原生加速 peer 不升级为必需运行时。
4. 回归使用真实临时包和可变对象验证共享与隔离，保留版本冲突三消费者反例，并增加删除后幂等复验。清单测试要求 ws 同时进入生产声明与有完整性摘要的锁记录。

## Alternatives considered

- 接受同版本、同字节副本：可让扁平布局继续出包，但不保护模块缓存、注册表和类身份，拒绝。
- 只增加修复轮数：不解决删除未被计入进展，且掩盖无法收敛的图，拒绝。
- 把本机 ws 拷进现有安装树：可临时补文件，但干净构建仍缺声明且改变已验收字节，拒绝。
- 同批重写整个依赖布局：可能解决实际打包阻断，但超出这次门禁修复，保留为单独工作，不把门禁修复称为布局修复。

## Consequences

此前被错误放行的真实依赖树会重新阻断构建，这是保护生效，不是发布完成。ws 声明只修复已确认的账户依赖缺失，不代表安装器启动与全部路径已经验收。保留既有 GUI 红项、固定 CI SHA 和正式安装包验收要求；不触发发布。

验证：修改前四项回归失败，修复后打包、实例与清单定向测试 65/65 通过；独立三模式反例变为拒绝拆分、拒绝合并、接受正确收拢。完整测试、真实打包与源码重启结果记录在[发布准备报告](../../../qa/results/2026-09-28-release-preflight/RELEASE-STATUS.md)。
