# Decision: 投喂余额与日志存量分离

Status: implemented

## Problem

[#120](https://github.com/ChisaAlter/Deepseek-Harness-Desktop/issues/120) 中累计已投喂量减去当前日志存量，导致清理日志后新增消费也不可投喂。真实压缩日志复现中，删除旧会话后新增 50 token，可投喂量仍为 0。原有测试只检查不出现负数，遗漏新增消费恢复。

## Decision

成长状态保留既有等级、累计投喂、日志存量和初始水位，新增版本化 food 账本：可投喂余额与按会话身份、turn/step 用量桶摘要保存的最大已观察值。扫描继续在 worker 中执行，仅处理用量数字。新增用量增加余额；消费减少余额；删除日志不撤销已获得的余额，恢复同一用量桶不再次发放。

旧状态第一次升级保留原有可用余额并登记当前语料，不凭空退款、不发放历史积压。发生过失配的旧状态保留成长值和累计已投喂值，之后的新消费立即可用。账本和成长值通过现有 config 的同一次保存持久化。

## Consequences

删除、恢复日志与应用重启不再重置或重复授予投喂信用。为防止恢复已删除日志产生重复信用，保留已观察桶的摘要，不记录消息正文。账本随使用增长；只包含摘要和数值，仍由现有配置保存路径管理，不新增后台服务或独立双写存储。旧版本回写不理解新账本，因此降级不能保证保留新余额。

验证覆盖真实 zstd 日志、删除后新消费、恢复旧桶、跨重启及既有扫描与桌宠集成；新安装包验收另行记录，不能继承旧候选结果。
