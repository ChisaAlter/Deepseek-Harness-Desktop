# Decision: 启动器首页使用单一启停入口

Status: implemented

中文 | [English](2026-09-29-launcher-home-state.en.md)

## Problem

启动请求等待期间只禁用被点击的按钮，另一处重试与插件恢复按钮仍可触发冲突操作。首页仍显示旧的未运行状态和重复的失败路径，让耗时启动看起来卡死。现场随后读取到 ready，不能把截图直接归因为永久挂起。

## Decision

启动、关闭、跳过插件与恢复完整插件共享前端操作锁。点击立即显示本轮状态与真实等待秒数，直到真实请求完成；不伪造进度、不用超时宣布后台已停止。失败后刷新状态并解除操作锁，旧状态请求不能覆盖新请求。

首页只保留一个启动/关闭入口，失败时启动按钮改为重试。原始错误仅显示在默认折叠的启动诊断，插件恢复操作也收进该处；本轮启动中隐藏旧诊断，无插件时不显示空列表。

## Alternatives considered

- 只删重复按钮不能消除其他恢复操作的并发，也不能修正旧状态，故不采用。
- 自动超时后重新启用启动按钮可能与仍在后台运行的启动竞争，故不采用。
- 删除完整日志会损失排障证据，改为折叠保留。

## Consequences

用户需展开诊断查看细节。隐藏 Electron 窗口使用真实页面和 preload，覆盖延迟请求、双击、失败、异常、再次启动、关闭，以及缩放后的按钮可达性。此测试不证明安装版的耗时已缩短；用户使用电脑期间不自动重启或操作其窗口。
