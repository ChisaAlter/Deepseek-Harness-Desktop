# Decision: Fork PR 使用显式目标仓库

Status: implemented

中文 | [English](2026-09-19-fork-pr-target.en.md)

## Problem

当 origin 指向用户 Fork，而 gh 选择上游作为 PR 目标时，旧逻辑将来源仓库与 origin 比较，误判为同仓库。创建命令传入无账号限定的 head，GitHub 无法解析来源分支。描述生成也错误地使用 origin 的基线。已审计现有决策目录，未发现持有该行为的记录；涉及其他模块 Fork 的记录与本问题无关。

## Decision

每次 PR 查询通过 gh 解析目标仓库 URL 和默认分支。一次创建操作复用同一目标，查询、创建及创建后查询显式传递目标仓库。来源仓库与实际目标比较，跨仓库创建使用 owner:branch；列表查询使用分支名，再核对返回项的来源仓库身份。

显式 gh-merge-base 配置保留优先级；否则同仓库保留已有跟踪分支规则，跨仓库使用目标默认分支。自动描述取与目标 URL 匹配的本地远程分支，缺少已拉取的目标基线时明确失败，不静默改用 Fork 基线。成功解析出不同目标时旧 PR 缓存失效；暂时无法解析目标时仍遵循既有短暂失败保留徽标策略。

## Alternatives considered

- 始终将 origin 当目标：无需额外查询，但会把本应发往上游的 PR 发到用户 Fork。
- 始终为 head 添加账号：可覆盖当前报错，但无法统一查询、目标默认分支和描述范围。
- 自动拉取缺失的目标分支：操作更少，但引入额外网络与本地引用变更；本次要求用户先拉取。

## Consequences

Fork 与同仓库路径使用一致的仓库身份，每次查询增加一次只读 gh 请求。目标解析或 PR 查询失败时不尝试创建；生成描述要求目标远程及其基线在本地可用。测试使用真实临时 Git 仓库和受控 gh 响应，不创建线上 PR；真实 GitHub 创建仍需用户主动执行。
