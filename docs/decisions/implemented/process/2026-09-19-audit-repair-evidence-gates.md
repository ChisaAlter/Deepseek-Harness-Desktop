# Decision: 审计修复以证据门禁收口

Status: implemented

中文 | [English](2026-09-19-audit-repair-evidence-gates.en.md)

## Problem

2026-09-19 的只读审计在脏工作树上运行，无法为每个脏文件建立逐字节的改动前基线；同时它发现的多数缺陷（清单丢失、取消传播缺失、权限策略过宽、验收脚本空转）都属于「本地检查全绿却仍然出事」的类型。若修复只以「测试通过」收口，就无法区分环境失败、既有失败、本轮回归与并发工作造成的阻塞，也无法阻止同一个缺陷以同样的方式再次逃逸。

真实运行还有两个同类维护风险。部分验收脚本为了构造测试工作区会执行 `git init` / `add` / `commit`，这与明确的 no-commit 任务约束冲突；为了跑 smoke 临时放宽约束，会让验收过程主动改变自己的前置环境。脏工作树中的并发任务也可能让后续门禁失败；若当前任务为了「把计划跑完」而修复或回滚别人的未提交修改，就越过了改动所有权边界。此时既不能把未执行的后续门禁记成 PASS，也不能在用户已经明确停止工作线后仍把它无限保持为「待完成」。

## Decision

本仓库的审计修复以证据门禁收口。每个阶段先定义可观察的验收状态，再执行与被改面相符的定向测试、治理/文档门禁与可行的真实运行验证；失败结果按环境问题、既有失败、本次回归、并发工作阻塞四类归因并如实记录。能机械判断的不变量（清单字段存在、超时仍然生效、验收脚本区分 SKIP 与 PASS、性能证据的输入身份完整）进入门禁脚本或契约测试，不留给评审记忆。计划与 owning 决策记录与非平凡实现同批维护，阶段证据保存为可独立读取的记录供复核。

真实运行脚本遵守任务级副作用约束。任务禁止创建提交时，smoke 使用显式的既有 Git 工作区模式：只读取调用方提供的工作区，临时 `userData` / `dsh-home` 与结果文件继续隔离；该模式不执行 `git init`、`git add`、`git commit`、checkout、branch 或 worktree 创建，清理也不删除调用方提供的工作区。默认 smoke 行为继续服务允许自行构造工作区的既有调用方，受限任务显式选择无提交模式。

门禁被当前任务所有权之外的并发未提交修改阻塞时，记录首次失败的准确文件、错误和执行阶段，不替其它工作流修复、回滚或弱化断言。依赖该门禁的后续步骤记为 **NOT RUN**，不得继承历史 PASS。用户随后明确停止该工作线时，以 **CLOSED WITH RESIDUAL WORK** 收口：已经完成的证据继续有效，阻塞项和未执行项继续显式保留；「工作线已关闭」不等于「全部验收完成」或「可以发布」。

## Alternatives considered

* **只跑一次全量 `npm test` 并以其结论收口** — rejected：全量结果里混着环境性失败；且清单丢失时全量测试本身无法启动，无法覆盖本次缺陷。
* **先修完再补门禁与文档** — rejected：维护系统要求非平凡改动同批写决策记录；后补会让「为什么这么定」与实现脱节，且缺陷可再次静默回归。
* **把审计的 W-only 发现也当作 HEAD 缺陷提交** — rejected：会把工作树状态误报为上游缺陷，污染事实层。
* **为了 smoke 在受限任务里临时创建提交** — rejected：验收不应通过违反任务约束来制造前置条件；既有工作区模式可以提供同一产品探针而不产生提交。
* **为了继续构建而修复或回滚其它并发工作流的未提交代码** — rejected：这会越过改动所有权，且把另一个产品缺陷伪装成本审计任务的修复。
* **遇到用户明确停止后仍把计划永久保留为 pending** — rejected：状态应反映事实；工作线可以关闭，但未执行门禁继续保持 NOT RUN / NOT MEASURED，不能把关闭等同于完成。

## Consequences

证据门禁使本地修复循环更长，但每个阶段的命令、退出状态、关键输出、阻塞项和未执行项都能被独立复核；SKIP 不再等同于 PASS，未运行的门禁也不能借用历史结果变成 PASS。无提交 smoke 模式依赖调用方提供一个可安全只读使用的现有 Git 工作区，因此它不替代对隔离性的检查。并发工作造成的构建失败可能让源码冒烟、打包或其它后续证据保持空缺；保留这些空缺比跨所有权修复更安全。`CLOSED WITH RESIDUAL WORK` 只表示该工作线停止并如实登记残余事项，不构成发布认证；安装器、远程、凭据、真实发布以及其它未运行面继续保留各自的人工或环境验收要求。
