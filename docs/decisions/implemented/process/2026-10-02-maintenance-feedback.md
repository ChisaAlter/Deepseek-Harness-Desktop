# Decision: 维护以当前事实和防复发证据为中心

Status: implemented

Hooks 执行约定已由[本地 QA 优先决定](2026-10-02-local-qa-first-release.md)替代；本文保留维护记录取舍和当时的验证边界。

## Problem

维护系统的格式检查能通过，但近期任务栏问题仍在真实 Shell 会话中出现。记录中的属性、迁移与构建成功没有覆盖可见结果。与此同时，普通行为修复会触发决策三件套、提案评审和多层同步，维护成本与防复发能力不匹配。规则引用校验漏检实际链接；本地 hooks 也不能仅凭安装说明假定已启用。

## Decision

[维护总览](../../../maintenance/README.md)成为当前执行入口。只为长期架构、兼容性、数据或流程取舍记录决定；普通修复使用现有测试、提交和 QA 证据。已授权工作可直接实施，新内部决定默认单语；已有双语记录和对外配对继续检查。备选只记录真实权衡，不设数量要求。

检查层次明确区分文档结构、产品行为和真实环境验收。重复故障先归因并保留可失败的复现，再核对测试实际进入 CI。对于系统缓存和安装条件，保留该环境的观察结果，未关闭的路径不能被其他层的绿灯覆盖。复盘只在漏检具有系统性价值时开展。

校验器按实际 Markdown 目标核对功能卡和规则引用。配对确认拒绝结构不一致的内容。归档支持单语，预检完整操作、不重写封存历史，异常恢复原文件。Git 集成可以只读检查实际配置，安装保留用户自定义 hooks 与 driver。

## Alternatives considered

- 只保留代码和测试、删除维护文档：降低写作量，但会丢失兼容性承诺、跨会话边界和不可自动化环境的证据。因此保留必要知识并收窄触发条件。
- 增加更多卡片字段、强制回归登记表或语义门禁：便于形式审计，但不能证明用户实际结果，还会增加同一事实的维护位置。因此复用模块测试、CI 和已有 QA 记录。

## Consequences

文档通过不代表 bug 已修复或新包通过验收。自动工具仍不能判断自然语言记录是否真实，也不能替代维护者审阅；新策略效果需从后续实际复发和交付结果观察。本次不会把未闭环的任务栏污染会话标为通过。

旧[双语配对决定](2026-09-17-bilingual-pairing-contract.md)的内部决定全量配对要求由本决定收窄；已存在配对的校验和对外文档同步继续保留。[取消字数门禁](2026-09-29-remove-doc-word-limits.md)继续有效。历史记录保留，不为改治理批量重写所有产品卡或重新执行产品安装验收。

2026-10-02 本地验证：Node 24.21.0 下维护工具及工作流定向测试 50/50 通过，文档门禁 7/7 通过；Git 集成安装后只读检查成功，实际调用 pre-commit 的结构检查 6/6 通过。与修改前 HEAD `6c641868632cd11771e676cb99bb829ed5ae45d0` 的三组隔离对照确认：旧版漏过断开的决策链接及伪装链接文字，新版拒绝；旧版归档在缺译文时已移走源文件，新版保留源文件。这些结果只认证维护工具，不代表真实 GitHub Actions 已运行、近期产品故障全部修复或安装版通过。
