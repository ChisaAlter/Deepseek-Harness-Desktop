# Decision: 源码发布验收跟随现行入口与可访问名称

Status: implemented

中文 | [English](2026-10-01-release-ui-walk-contract.en.md)

## Problem

源码发布验收仍观察独立远程侧栏行、未登录账户的旧反馈文案和凭据状态的可见文字。现行产品将远程收束到账户菜单，未登录状态使用「联系我们」，会话日志开关用 `aria-labelledby`，已配置凭据用带可访问名称的图标。旧观察点使真实路径无法通过验收。技能探针在目标页未就绪时也返回对象；第二次推理切换前的停止等待超时又被当作成功，掩盖了实际未就绪状态。

## Decision

- `release-ui-walk` 解析标准 `aria-labelledby` 名称，并继续要求未登录菜单同时提供登录与联系我们。
- 保留 required 步骤 `remote.footerPresent`，其含义按现行账户入口契约解释：账户存在时必须没有独立远程行，点击账户菜单远程项后必须打开原配对弹窗；账户缺席时必须通过侧栏回退打开同一弹窗。
- 自定义提供商提交后，在原有 12 秒保存预算内重新打开模型页，必须同时看到提供商条目与已配置凭据的可访问名称。草稿字段、其它位置的名称、缺失凭据均不能通过。
- 技能探针只在正确导航激活且标题、添加按钮都出现后完成；失败记录导航和内容状态。停止模型 ping 后先等空输入框离开停止状态，再写回一条不发送的验收草稿，必须看到可编辑输入框、可用发送按钮且没有活动停止按钮，超时明确失败。空草稿本来就禁用发送，因此两阶段共用原等待预算。既有超时不延长，required 步骤不删除、不改为 optional。

## Alternatives considered

- 保留旧观察点可以避免改测试，但会要求产品恢复已废弃入口和文案，与现行契约冲突。
- 删除失败步骤或只检查配置落盘可以快速恢复绿灯，但不能证明用户能通过实际界面完成操作，也不能发现凭据保存或停止状态故障。
- 增加等待时长可以容忍慢重载，但不能修正错误选择器或立即返回的探针，也会让明确未就绪状态被长期掩盖。

## Consequences

VM 页面测试执行实际注入 helper 和点击流程，覆盖缺弹窗、重复远程入口、错误技能导航、未保存凭据、禁用发送与活动回合的反例。测试夹具要维护少量 DOM 接口；真实源码 UI 仍须独立复跑，这些定向测试不证明安装包验收完成。

本记录与[远程账户入口决定](../product/2026-09-23-remote-account-menu.md)及[修复证据门禁](../process/2026-09-19-audit-repair-evidence-gates.md)部分重叠，沿用两者的产品路径和证据强度，不取代它们。产品行为与[账户入口卡](../../../features/account-settings-entry.md)保持一致。
