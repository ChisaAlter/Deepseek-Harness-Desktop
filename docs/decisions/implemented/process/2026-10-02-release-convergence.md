# Decision: 以固定候选和影响范围收敛发布

Status: implemented

中文 | [English](2026-10-02-release-convergence.en.md)

## Problem

0.3.3 多次构建成功后仍未放行；候选不断替换，整表验收、工具误判和环境状态混在同一循环。仅凭源码绿灯遗漏安装问题，而每次局部修复重做全部场景又无法稳定结束。发布需要可执行的范围、真实质量和明确的责任签字。

## Decision

[发布操作流程](../../../handbook/modules/release-process.md)成为唯一当前执行规则。开发期按风险做定向验证，稳定候选执行完整自动矩阵；生成目录和治理前置。候选构建检查最新同 SHA main push 的共享与目标平台 CI，以最近正式版为基线生成不可变计划；Windows 不因非交付 macOS job 失败阻塞，DMG 交付仍要求其测试与安装验收。

计划保留 26 项固定安装核心场景，按全部变更路径选择影响用例；依赖、上游、核心和未知源码变化进入完整库。完整库保留具体步骤，旧 P0/P1/P2 不再混同缺陷严重度。首次 packaged smoke 失败停止，不以内置重试掩盖首启问题。断线下载按不可变 artifact ID 续传并校验摘要。

每个候选只有一份 JSON 当前记录，包含原始 Setup/DMG 摘要、计划摘要、环境、结果、缺陷与签字。核心缺证据、严重产品缺陷、未知失败阻止发布；非核心限制按真实风险记录，豁免有责任人、理由、跟进与到期日。晋级读取 main 上不可变提交的报告，验证原包后发布计划、报告、限制和校验和；补报告不重建二进制。自动校验不能证明证据内容真实或替代人的授权。

## Alternatives considered

- 每次修复重跑所有本地和实机用例：选择逻辑简单且覆盖广，但无法区分新风险与已知环境失败，换包不断使工作重启。
- 只凭 CI 绿色发布：周转快，但不能认证安装、升级、Shell 缓存和真实退出。
- 仅修改文档：部署成本低，但机器仍会允许缺安装验收的晋级，身份也容易漂移。
- 自动继承旧包未改模块的 Pass：更省时，但运行时装配和跨模块影响难以证明；本方案保持新包核心重新执行，未选项明确未执行。

## Consequences

正常局部发布不再重复整库；广泛改变运行时的候选仍可能需要完整验收，不能承诺任何版本都在固定小时数内发布。影响映射需要随模块演进维护，未知路径保守进入完整库；人工必须审阅 diff 并补充漏选风险。证据公开前须脱敏，签字真实性由负责人审阅。

旧候选缺少新计划和校验工具，不能伪造追认；本流程首次使用需要新的候选。工作流保留既有包字节和 tag 不可变约束，不重新构建晋级对象。本地行为及接线验证不等于真实 GitHub Actions、实机安装或公开发行通过；执行结果在 [feature 卡](../../../features/release-process.md)记录。
