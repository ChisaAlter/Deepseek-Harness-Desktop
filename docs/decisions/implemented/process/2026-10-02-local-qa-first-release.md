# Decision: 先完成实现和本地实际 QA，再进行最终 CI

Status: implemented

## Problem

自动 push/PR CI、文档 hooks、默认全量门禁和三遍相同 GUI 测试把诊断、开发、维护格式和交付混成一条长链。本地锁文件错误也被推到 CI 才发现；文档绿灯没有证明原失败场景已修复。用户明确要求停止这一工作方式。

## Decision

以[WhaleIsle 唯一维护准则](../../../maintenance/README.md)为执行权威，[发布操作说明](../../../handbook/modules/release-process.md)只细化原包交付，先完成实际实现，再准备并完成必要本地测试、严格 QA 和真实操作，最后才手动 CI。禁止提前准备测试和为假想风险增加产品防御。保持原包身份、实际安装、受影响行为和真实失败边界检查。

撤销 push/PR 自动 CI；所有最终测试 job 检出明确候选 SHA。macOS 只在交付 DMG 时选择。删除 fast-checks 与 desktop 测试集的重复回归、hooks 中自动文档检查、默认全量门禁和三遍相同 GUI 执行；相关结构/配对工具保留为按变动手动使用，已有行为测试不删除。

维护执行以[维护总览](../../../maintenance/README.md)为唯一准则，按阶段、负责模块和证据类型分工；技能与 rules 链接权威位置，不复制验证清单。结构、模块行为、装配、实际环境和交付身份分别认证。新增门槛须说明已证明漏检、独立价值、触发及调整条件，不为假想风险增加防御。

pre-push 只在自动/未知工作流策略下复用单份状态核对同 HEAD QA，不启动套件；手动入口不把普通推送升级为发布门槛，最终 CI 前仍须核对。维护检查同时选择模式时去重；撤销与当前开放远程入口契约冲突的暂存区守卫，实际远程边界仍由产品测试覆盖。QA 观察器和执行提示不自动扩大产品候选范围，未知产品源码仍保留完整范围。

CI 次数跨提交、版本、候选、工作流和会话累计；第四次未通过停止 CI/新候选，核查本地漏检并由用户决定纠正后恢复。计数未知保持未知，输入来自实际 run/attempt 历史，不能填零清账。恢复摘要绑定不变的当前累计次数，包含真实用户决定和纠正验证；新增未通过后旧恢复决定失效。工具核对一致性，不认证授权真实性。

此决定替代[发布收敛](2026-10-02-release-convergence.md)中的自动 CI/治理前置约定，以及[维护系统收敛](2026-10-02-maintenance-feedback.md)中的 hooks 执行约定；两者原包晋级、证据身份与历史事实保持有效。

[旧双语迁移决定](2026-09-17-bilingual-pairing-contract.md)与[旧审计证据门禁决定](2026-09-19-audit-repair-evidence-gates.md)保留历史理由，但全量配对、提交前门禁、普通修复强制记录和提前准备验证的执行约定不再有效。功能卡的 Gates 只定位实际风险对应的验证入口，不能恢复这些旧约定。

## Consequences

已移除上游每文件 100% 数字覆盖率阈值及字数门禁、远程子项目强制 hooks 安装和旧 Node 22 钉版；DSH hook 安装器在本项目让位给宿主。清理旧测试阶梯、逐模块审查/原型审批/重复自检要求，模块指令只链接唯一准则，历史与快照夹具保留。必要行为断言、实际装配、权限和数据兼容契约不削弱。

维护流程按真实风险收敛；不再为一个局部修改自动重复构建和全表测试。全局文档、插件、hook 和工作流输入都不能证明观察真实性或保证代理百分之百遵守，也不能拦截所有外部 API；必须如实报告实际修改、验证和阻塞，禁止把接线成功称为产品已交付。

本地接线行为和真实 Git hook 操作在实现完成后验证；未运行的 GitHub 工作流、现有候选缺陷与尚未完成的安装验收保持未验证/阻塞，不因本次规则修改变成通过。当前验证入口见[发布流程卡](../../../features/release-process.md)。
