# Decision: 鲸鱼娘优化的局部回退与发布阻断

Status: implemented

中文 | [English](2026-09-24-whale-performance-partial-rollback.en.md)

## Problem

性能优化缺少同条件修改前后对照和完整视觉、跨屏、自动降级启动验收，却引入了默认无人交互 60 fps 限制、睡眠 200 ms 推理节拍和 Anime4K 延迟加载。打包修复进一步允许同一源依赖在顶层版本冲突时变成多个模块实例；文件和版本一致不能证明模块级共享状态等价。用户要求停止开发、重新审查，并批准按审查建议局部回退。

记录审计：[原优化决定](2026-09-24-whale-runtime-footprint.md) 与本决定部分重叠，其渲染调度、Anime4K 加载顺序和依赖身份豁免部分由本文取代；写盘、资源去重和请求去重的理由仍适用。live-first 引擎和既有设置、交互决定不被本次回退取代。

## Decision

- 恢复原有 `tickStill`、推理完成回调和 rAF 的绘制关系，撤销无人交互 60 fps 上限和睡眠 200 ms 节拍。推理仍为 50 ms，只有用户开启省电且空闲五分钟后为 110 ms。保留默认关闭的性能计数与普通成长快照不唤醒修复；测量脚本同步读取恢复后的节拍。
- 恢复 HTML 中 Anime4K 的静态脚本入口，移除运行时加载 helper 和等待。引擎、模型、超分和离线降级链保持原路径。
- 对任意同源依赖拆分恢复构建失败；顶层版本或 peer 冲突不能豁免。保留不同源实例禁止合并、运行时文件和依赖图检查、测试专用包排除及真实 CLI 门禁。其余工作区依赖重排冻结，不继续开发；当前已知依赖拆分仍是发布阻断项。
- 保留无变化写盘抑制、保存失败重试、正常关闭补存、相同 shell 去重和不可达资源过滤。活跃时长按分钟保存意味着异常退出可能丢失约一分钟统计。保留快捷对话历史与目录分别去重；每分钟目录刷新和完整历史尾请求只算部分实现，不声称完成原计划的十分钟不重复目录请求或历史增量目标。

## Alternatives considered

- **全部回退本次改动** — 能恢复更多原始路径，但同时失去有独立依据的写盘与重试修复；原打包流程本已存在旧依赖抢占问题，全部回退不能证明可发布。混合工作区也要求按具体改动段处理。
- **继续修复依赖布局并保留渲染实验** — 可能最终实现性能目标，但需要新的实现和尚未完成的验收，与本轮收敛回退的范围不符。
- **保留依赖拆分豁免** — 可使构建继续，但无法保证模块级共享状态，违反依赖身份检查的目的，因此撤销。

## Consequences

回退恢复既有显示节拍，也恢复其较高绘制成本；不声称获得 CPU、GPU 或内存净收益。原始资源排除约 13.85 MiB 不等于安装包净节省。针对顶层版本冲突的三消费者反例必须阻断，顶层可共享的正例仍须共享同一对象。

本轮验证覆盖定向测试、全量测试、文档治理和源码重启；不重新构建安装包。原 final7 构建已按用户要求中断，现有 dist 产物不作为交付物。三次同场景性能对照、三十分钟写盘观察、四条自动降级冷启动及完整跨屏视觉验收仍未完成；保留代码不等于这些优化已通过发布验收。
