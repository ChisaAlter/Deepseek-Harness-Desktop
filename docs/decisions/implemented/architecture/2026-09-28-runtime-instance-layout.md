# Decision: 运行时按源实例装配并在解压后恢复链接

Status: implemented

中文 | [English](2026-09-28-runtime-instance-layout.en.md)

## Problem

严格门禁恢复后，真实安装树在两个 send peer 实例被合并处失败；旧拍平模型也会把共享依赖拆成多个缓存实例。只靠发布文件相同或局部嵌套无法表达原始依赖图。用户在门禁修复后要求全面修复，授权继续处理实际布局及发布前全部红项。

记录审计：[局部回退决定](2026-09-24-whale-performance-partial-rollback.md) 的显示与持久化取舍仍有效，本决定仅取代其后续依赖布局冻结；[门禁修复](../bug-fix/2026-09-28-packaging-identity-gates-and-ws.md) 的严格身份检查继续有效。原发布链和生产安装包验收规则不变。

## Decision

- 以源目录 realpath 为实例键收集生产依赖、已安装可选依赖和 peer 闭包。循环用已访问实例收敛；缺少必需依赖、测试专用包、预算超限或目标冲突均失败。
- 工作区包保留原 `apps`、`packages`、`vendor` 相对位置，避免改变相对资源路径；第三方包每个源实例只有一个短目录，目录 ID 为相对来源路径摘要。每条消费者依赖指向对应的唯一目录，根名称入口也使用链接。
- `.dsh-runtime-links.json` 的 version 1 只保存根内相对 path/target。构建时恢复链接，独立比较每个包的发布文件和实际解析边；归档前移除链接，因此 tar 只含普通文件与清单。解压后先恢复链接再验收并写完成标记。
- Windows 使用普通用户可创建的目录 junction，其他平台使用目录符号链接。迁移后根据新根重建目标，不携带构建机绝对路径。拒绝越界、重复、替换普通目录及逃逸的父链接。
- 显式 deploy 与完整源码装配经过同一个实例图校验。既有身份错误反例保留，不以豁免或跳过测试换取出包。

## Alternatives considered

- 接受等字节实例合并或强制副本：可继续出包，但改变共享状态、注册表和类型身份，拒绝。
- 继续增加拍平收拢轮数：对不存在可共享祖先位置的图无效，也不解决异源合并，拒绝。
- 把绝对 junction 直接打入 tar：制作简单，但迁移后指向构建机目录；相对 Windows symlink 又可能要求用户特权，拒绝。
- 使用自定义 Node 模块解析钩子：不需文件链接，但会新增 CommonJS、ESM、原生包和子进程的解析协议，维护成本更高，拒绝。

## Consequences

增加一个受版本约束的装配清单和首次解压链接创建成本，换取与源码相同的模块实例图。实例目录仍需遵守源码依赖声明；未声明的动态依赖不在闭包保证内。Windows junction 的迁移通过重建处理，归档本身不依赖创建 symlink 的权限。旧无清单包保留既有提取路径。

验证包括真实 CJS 共享/隔离、循环、tar 搬迁、路径拒绝、既有提取回归和完整运行时 CLI；结果与发行状态见[发布准备报告](../../../qa/results/2026-09-28-release-preflight/RELEASE-STATUS.md)。本地包不替代 CI Setup 的同 SHA 验收。
