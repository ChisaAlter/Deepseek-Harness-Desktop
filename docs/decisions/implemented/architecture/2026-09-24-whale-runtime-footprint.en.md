# Decision: Persist whale state on change and coalesce Canvas paints

Status: implemented

[中文](2026-09-24-whale-runtime-footprint.md) | English

Partially superseded: the rendering schedule, deferred Anime4K loading, and dependency identity exemption below were withdrawn by the [partial rollback decision](2026-09-24-whale-performance-partial-rollback.en.md). Those passages remain review history, not current requirements. That record also states the acceptance limits of retained changes.

## Problem

The pet log watcher saved its watermarks unconditionally every two seconds. Desktop `saveConfig` rewrote both configuration and encrypted credentials, while the usage mirror included the current timestamp in its comparison and was rewritten on every poll. Four consecutive observations showed both files changing about every two seconds. The renderer also called `paint()` from `tickStill`, inference completion, and rAF; the live path cleared dirty regions on every paint and the rig fallback cleared the full Canvas. The package included an unused 1024² model, an old rig backup, and ten byte-identical expression shell images.

## Decision

The watcher keeps active time in memory, saves log offsets, event state, and reminder watermarks as soon as they change, and checkpoints elapsed active time at most once a minute when that is the only change. Normal shutdown flushes any shorter remainder. It compares the normalized persisted projection so in-memory cursors beyond the config cap do not trigger repeated writes. The usage mirror records a snapshot only after atomic replacement succeeds and retries failures on the next poll; its timestamp changes only with business fields. rAF now paints after state updates at up to 60 fps while unattended, inference completion only updates the newest frame, and inference slows while automatically asleep. Ordinary minute growth-rescan snapshots no longer wake her; actual feeding or level-up still does. Timing and frame counts are recorded in memory only when measurement is explicitly enabled. Package filters exclude unreachable HD resources, the old backup, and duplicate shells; the rig manifest reuses the existing image and the loader decodes each path once. Anime4K loads after the live model is ready, so fallback paths do not parse its roughly 9 MiB script. Quick chat still syncs the session tail every three seconds but refreshes the model catalog on opening and about once a minute. History and catalog requests are coordinated separately so a slow catalog does not block history; an empty catalog counts as loaded, and reopening queues a forced refresh after any in-flight catalog request. After flattening pnpm, the complete workspace runtime package replaces a same-named old package before nested version isolation is calculated. Old pnpm host entries for replaced workspace packages are skipped, and each declared runtime edge is checked against the final package files and resolution graph, with only necessary nested instances restored before the real CLI contract is checked.

Vendored Cordis packages are replaced in full alongside workspace packages so peer consumers do not pick up old top-level versions. An existing instance is reused only when published files and the dependency resolution chain match the source; conflicts are repaired recursively, with peers placed where their consumer can share them. The `dsh-client-test-runtime` and `dsh-session-snapshot` packages are excluded because their consumers declare them only for development. A direct declaration of either package in dependencies, optionalDependencies, or peerDependencies of a collected workspace or vendored package fails the build. This gate does not prove the absence of third-party transitive, aliased, or dynamic consumers. The managed graph checks published files and resolution edges. It rejects needless identity splits when the same source instance can be shared from the top level. Conflicting top-level versions or peer contexts keep nested copies, whose count is reported. The final tree also rejects either test-only package before the real CLI contract.

## Alternatives considered

- **Replace polling with file system events** — rejected: logs append zstd frames, while events may be coalesced or arrive before a frame is complete. The existing offset poll and torn-frame handling are reliable; skipping unchanged persistence removes the main write load.
- **Change the current clear rectangles** — rejected: Windows layered transparent windows previously showed trails, black edges, and drag flicker. This change only removes duplicate paints while retaining the clear strategy.
- **Remove one ORT/WASM binary or the rig fallback** — rejected: WebGPU/JSEP and CPU WASM use different backend files, and offline fallback is a product contract. Only verified unreachable resources are excluded.

## Consequences

Idle use no longer rewrites config, credentials, and usage mirror periodically. Normal shutdown flushes active time; an abnormal exit may lose up to about one minute. Events and log offsets remain promptly persistent. A completed inference frame may wait until the next display refresh; interaction follows the display, while unattended Canvas paints cap at 60 fps. Package savings must be measured from a new asar and installer build, not inferred from raw source bytes. The current rig expression shells were already identical; sharing their file preserves the present fallback appearance. Fixing those art variants later requires revisiting the package filter. Workspace replacement makes the real CLI use current compiled Harness packages while preserving nested old versions needed by consumers and isolating current workspace package dependency instances.
