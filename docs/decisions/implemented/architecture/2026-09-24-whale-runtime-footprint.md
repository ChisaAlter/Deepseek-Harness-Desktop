# Decision: 鲸鱼娘按变化持久化并合并画布绘制

Status: implemented

中文 | [English](2026-09-24-whale-runtime-footprint.en.md)

部分取代：下文的渲染调度、Anime4K 延迟加载和依赖身份豁免已由[局部回退决定](2026-09-24-whale-performance-partial-rollback.md)撤销；对应段落保留为审查历史，不再是现行要求。其余保留项的验收限制也见该记录。

## Problem

桌宠日志观察器每 2 秒无条件保存水位线。桌面 `saveConfig` 同时重写配置和加密凭据；用量镜像把当前时间放入比较内容，也每轮重写。实机连续四次观察到两个文件约每 2 秒修改一次。渲染器在 `tickStill`、推理完成回调和 rAF 中重复调用 `paint()`；Live 路径每次都清理脏矩形，rig fallback 每次全清屏。发布包还包含当前不会加载的 1024² 模型、旧 rig 备份和十张字节相同的表情壳文件。

## Decision

日志观察器保留内存中的当前活跃时长，日志偏移、事件状态和提醒水位线变化时立即保存；只有活跃时长增长时至多每分钟检查点一次，正常关闭时补存不足一分钟的尾段。比较规范化后的落盘状态，避免内存游标超过配置上限后每轮重复保存。用量镜像比较业务字段，原子替换成功后才记录已写快照，失败则下轮重试；时间戳只在这些字段变化时更新。Canvas 由 rAF 在状态更新后统一绘制，无人交互时最高 60 fps；推理回调只更新最新帧，自动睡眠时推理节拍降低；每分钟成长值重扫的普通快照不再被当作互动叫醒，实际投喂或升级仍叫醒。按需测量时才在内存里记录耗时和帧数。发布过滤器排除不可达 HD 资源、旧备份和重复壳；rig manifest 复用同一现有图像，运行时按文件路径只解码一次。Anime4K 在活体模型准备就绪后加载，使降级路径无需解析约 9 MiB 脚本。快捷对话卡仍每 3 秒同步会话尾，模型目录只在首次打开及约每分钟刷新；历史与目录分别请求和去重，目录慢时历史照常刷新；空目录算作已加载，重开卡的强制目录刷新在既有请求结束后补做。Harness 的 pnpm 拍平会遇到同名旧包，复制完成后先以当前工作区的完整运行时包替换同名旧包，跳过旧工作区包的 pnpm 宿主条目，按最终发布文件与实际解析链逐条补充必要的嵌套隔离，并复验传递依赖与 peer，最后执行真实 CLI 契约检查。

补充：vendored Cordis 与工作区包一同完整替换，避免旧顶层版本被 peer 消费者解析。只有已声明依赖在源树和目标树的发布文件及解析链均一致时才复用已有包；冲突时逐层复制，peer 放在消费者可共享的位置。仅被开发依赖引用的 `dsh-client-test-runtime` 与 `dsh-session-snapshot` 从发布树排除，若收集到的工作区或 vendored 包在 dependencies、optionalDependencies 或 peerDependencies 中直接声明这两个包，则构建失败；第三方传递依赖、别名和动态加载不在该门禁的证明范围。完整依赖图核对发布文件和解析链；若同一源实例可从顶层共享，则拒绝不必要的身份拆分。顶层版本或 peer 上下文冲突时保留嵌套副本并记录数量；最终发布树还断言测试专用包不存在，通过后再执行真实 CLI 契约检查。

## Alternatives considered

- **停止轮询并改为文件系统事件** — rejected：日志为持续追加的 zstd 帧，文件事件会合并或先于完整帧到达；现有偏移轮询和撕裂尾帧处理已验证可靠。只跳过无变化持久化即可去除主要写盘。
- **改动现有清除矩形** — rejected：此前在 Windows 分层透明窗上出现残影、黑边和拖拽闪烁；本次只去除同一刷新周期的重复绘制，保留清除策略。
- **删除一份 ORT/WASM 或取消 rig 降级** — rejected：WebGPU/JSEP 与 CPU WASM 使用不同后端文件，离线降级链是产品契约；只排除证实不可达的资源。

## Consequences

长时间空闲不再周期性重写配置、凭据和用量镜像。正常关闭会补存活跃时长；异常退出时最多丢失约一分钟；事件和日志偏移仍即时持久化。推理完成到显示可能等待下一个刷新周期，交互跟随屏幕刷新率，无人交互时画布最高 60 fps。打包体积要以新构建的 asar/安装包验证，源码原始字节节省不等同压缩包节省。rig 的现有表情壳本来完全相同；共用文件不改变当前 fallback 画面，未来若修复表情素材须同步撤销相应过滤。工作区替换步骤确保真实 CLI 使用当前编译的 Harness 包，并在确定顶层包来源后保留旧消费者所需的旧版嵌套包，同时隔离当前工作区包自己的依赖实例。
